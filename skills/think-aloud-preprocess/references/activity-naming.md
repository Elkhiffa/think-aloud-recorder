# 内容概括与场次命名

像给聊天会话自动起名一样，概括本场具体体验了什么，让人从名称辨认这段内容并找到后续分析材料。按当前有效事件逐段核对实际参与的任务、区域、玩法与目标，组合成如【清河任务+探索+止戈+萌宠争锋】的名称。保留有意义的多条内容，未知区间照实说明；不能把“尽量列全”写成已经确认毫无遗漏。示例只说明风格，不能套用未在素材中出现的活动。

## 内容取舍

- 优先保留有辨识度的区域/任务线、任务名、玩法或活动专名，以及本场的具体目标。例如有依据时使用“清河任务”“止戈”“萌宠争锋”；具体内容可以与“探索”这样的补充词并列，不强求所有项处于同一分类层级。已有明确玩法名时保留其名称，不再压成“战斗”“小游戏”等宽泛类型。
- 从本场事件归纳名称，不先套固定分类词表。宽泛词仅用于素材没有更具体依据或需要概括零散活动时；不要为增加辨识度猜任务名、地点或模式。游戏专名结合现有画面、原话与已核实术语确认，转写不可靠时采用可信的描述。
- 尽量列出涉及的独立内容，不只选时长最长的一项，也不限三个。合并重复和同义项，保留任务之外实际参与的探索、独立玩法及有意义的养成目标；无须把每次菜单、按键、路过或任务内每场小战斗列成流水账。跨场次统一同一内容的称呼，但不同任务、地区和玩法不应都归成一样的粗分类标题。通用活动大类若有比较价值，另外留在分析报告中。
- 仅在对白里提及、计划但未实施或纯猜测的活动不计入；念任务文案不自动证明完成任务。每个内容项至少关联一个当前结果中的事件，语义依据由整理者检查，接口只验证引用有效。
- 名称用【内容一+内容二+内容三】组合，不默认加游戏名、日期或情绪结论。完整保留有依据的独立内容，不按100字短标题限制删项；合并重复表达，不直接截断或仅保留前三项。无法识别有依据的内容时保留未命名并说明限制。
- 有手动名称时，保留其原文作为前缀，在后面用空格追加【内容摘要】，例如“第一次到清河【个人备注】 【清河任务+探索+止戈】”。接口分别保存手动前缀与自动摘要，再次整理只替换自动部分，不重复堆叠；不要自行解析任意方括号或先拼接 expected_name。原自动名可据已有证据修订，本轮已处理的手动名也可补摘要。用户改名后重新读取并保留新手动部分；清空名称后只使用自动内容名。只改显示元数据，不改目录、游戏/预设名或源素材。

## 读取、预览和保存

先检查实际运行的 CLI `--help` 是否包含 `name-activities`。追加手动名摘要还要求命名上下文返回 `naming_policy="append-content-v2"`；旧接口仅保留手动名时不要宣称已追加，先升级获准使用的 CLI。这是独立于 v1 事件结果的附加接口，旧安装不一定具备；用户指定已验证的开发检出时可使用该检出的 CLI，否则保留建议并说明缺少入口。不要把新字段塞进旧版 `submit` 候选期待它自动保存，也不直接编辑 session.json。

```powershell
& "$app\runtime\python.exe" "$app\agent_cli.py" name-activities "$session"
# 在资料库外写活动候选后，预览并核对：
& "$app\runtime\python.exe" "$app\agent_cli.py" name-activities "$session" --file "$candidate"
& "$app\runtime\python.exe" "$app\agent_cli.py" name-activities "$session" --file "$candidate" --apply
```

无 `--file` 时只返回当前素材/结果身份、`expected_name`、`manual_name`、`naming_policy`、`can_auto_name` 和既有活动命名信息，不返回运行配置。`can_auto_name=false` 只表示存在手动前缀，仍可按新策略追加摘要，不应跳过。有手动前缀时由接口自动拼接，候选只填具体内容项。只有当前有效且已完成的预处理结果可命名；仍在重新整理时等待提交。已有 complete 结果可直接补活动分类，无须领取新任务或重做事件。

候选 JSON 使用本次读取返回的真实值。接口字段仍叫 `activities`，其中 `name` 是上述具体内容标签，没有固定分类枚举。`expected_name` 是场次自定义名称，未命名时为 `""`，不要填游戏默认标题。以下事件编号和内容仅为格式示例。

```json
{
  "version": 1,
  "session_id": "读取返回的场次ID",
  "revision": "读取返回的素材revision",
  "result_sha256": "读取返回的结果SHA256",
  "expected_name": "",
  "worker": "本次会话标识",
  "activities": [
    {"name": "清河任务", "event_ids": ["e1"]},
    {"name": "探索", "event_ids": ["e2"]},
    {"name": "止戈", "event_ids": ["e3"]},
    {"name": "萌宠争锋", "event_ids": ["e4"]}
  ]
}
```

`--apply` 在场次锁内核对素材 revision、结果摘要和名称，再原子保存 `session.json` 的 `activity_naming`；同时保存组合后的 `session_name`。手动前缀原文单独存为 `activity_naming.manual_name`，自动部分存为 `suggested_name`；有前缀时返回 `manual_name_preserved=true`、`manual_summary_appended=true`，含义是前缀保留且已追加，不是整个显示名称未改变。回读无 `--file` 的上下文确认；保存成功与分类完整性分别报告。不要把返回的完整上下文（尤其旧 activity_naming）当新候选，按以上结构取字段即可。

名称中途改变时拒绝写入，重新读取后保留新手动部分再预览。结果摘要变化时重新核对事件，不能只替换摘要硬提交。同一候选重试、且显示名称未再改变时幂等；不改录像、事件结果、就绪信号或租约，不让命名触发预处理重跑。活动分类绑定结果摘要；后续素材或事件重做后需重新核对，旧类型不自动视为有效。

组合名称已放宽到4096字，用于异常输入保护，不作为压缩标题的目标。一场最多32个内容项，每项名称最多24字；不允许内嵌加号、方括号或控制字符，以免组合名称产生歧义。每项 `event_ids` 至少一条且全部存在于当前正式结果中。接口不能自动确认语义准确或覆盖完整，仍须人工式证据审查。
