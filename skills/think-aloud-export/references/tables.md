# 读表与填表

## 列用途表

按表头文字认列；同一用途可能有不同叫法。认不出的列留空。

| 用途 | 常见表头 | 填什么 |
|---|---|---|
| 界面一级 | 一级、系统、模块 | `screen_path[0]`；HUD 等非界面场景（`screen_context`）填“HUD”或表里已有的近义词 |
| 界面二级 | 二级、功能 | `screen_path[1]`，没有就同一级 |
| 模块 | 模块（只有一列界面时） | `screen_path` 用 `/` 连起来，或表里已有的模块名 |
| 问题描述 | 问题描述、问题描述或定位 | 一句“界面 + 现象”，见下面写法 |
| 问题类型 | 问题类型、类型（取值是走焦问题、键位问题这类时） | 表里已有取值；可多选时用表里的写法（如“走焦问题,操作逻辑”） |
| 截图 | 截图（可有两列） | 图片，`write_sheet.py` 上传后填入 |
| 优先级/严重程度 | 优先级、参考优先级、严重程度 | 表里已有取值；按影响定，见下面 |
| 区服 | 国服/海外 | 表里最多的那个 |
| 平台 | 三端 | 手柄问题填“手柄”，通用问题填“all”（照表里写法） |
| 反馈人 | 反馈人、提出人 | 本人 |
| 跟进人、单号、QA、单子状态（自动） | — | 留空 |
| 处理状态 | 处理状态、状态、单子状态 | 表里表示“还没处理”的词（未处理、未提单）；表里没有就留空 |
| 类别 | 类别（BUG/优化）、类型（bug/需求） | 明说的 bug → BUG 词；其余 → 优化/需求词；疑似 bug 填 BUG 词，在汇报里说明 |
| 改法 | 改法、问题备注（预期解决方式）、建议 | 记录者说出的改法或期望；没说就留空，不替设计师想方案 |
| 职能 | 职能 | 只有原话或陈述里说清了是谁的问题才填；否则留空，不算待定行 |
| 备注 | 备注 | 只放截图列放不下的截图链接；不写原话、场次、待定说明 |

## 问题描述写法

像 bug 单的标题：先说在哪，再说现象，一句话，二三十字为宜。照表里已有的口吻写。

| 判断里的陈述 | 填进表里 |
|---|---|
| 从瓷窑页退回清河家业后，记录者说“我从哪儿进来的哦？”……画面没有面包屑或来源提示。 | 家业多层页面进出后找不到来源，缺少返回路径提示 |
| 打开伙伴详情后按方向键，焦点在左侧列表和右侧详情之间来回跳…… | 伙伴详情走焦应该是父子级关系 |

不写“记录者说”“画面显示”这类过程词，也不引原话：读表的 QA 和策划不知道场次和原话。

## 优先级 / 严重程度

- 高 / 阻塞：卡住流程、无法继续、功能不可用。
- 中 / 严重：能绕过但明显费力，或高频出现。
- 低 / 一般：偶发、轻微不顺手。
- 记录者自己说了“很严重”“小问题”的，按他说的。拿不准就留空，汇报里列出。

## 范例一：手柄跑测表（H72手柄UX跑测问题记录2026）

- 每月一个 sheet（如“手柄跑测26.10-11”），第 1 行是表头，15 列：
  一级｜二级｜问题描述｜问题类型｜截图｜截图｜优先级｜国服/海外｜反馈人｜跟进人｜处理状态｜类别｜单号｜QA（优化内容不用提单）｜备注（优化内容不用提单）
- 问题类型取值：走焦问题、键位问题、操作逻辑、焦点裁切、焦点丢失、操作提示。
- 类别：BUG / 优化。优先级：高 / 中 / 低。处理状态：处理中 / 已修改 / 暂不处理（新导出的填“未处理”，表里有这个词时）。
- 主题：手柄。只导手柄相关问题（走焦、焦点、键位与按键提示、手柄下的操作逻辑）；键鼠专属问题、纯视觉或文案问题不导。
- 手柄通用预期：写问题描述和判断 BUG / 优化时用得上。违反下面这些、而游戏别处做得对的，多半是实现问题，填 BUG：
  - 打开界面或面板时，初始焦点落在主要内容上（例：搜刮面板打开时焦点应在容器物品，不在自己背包）；
  - B 返回上一级，不直接关掉整个界面；
  - 键鼠能点到的，手柄都能走焦到达，不需要绕路或只能按别的键打开；
  - 同类控件的走焦方式一致（同一游戏里页签、列表、焦点组的进出规则相同）。
  只说“用手柄很难、很麻烦”的，问题描述要写清难在哪一步，填优化。
- 一行示例：`伙伴｜伙伴详情｜伙伴详情走焦应该是父子级关系｜走焦问题｜<图>｜｜中｜国服｜保杰｜｜未处理｜BUG｜｜｜`

## 范例二：UX 验收表（如「UX验收表【摇摇马】」）

- 一个玩法一个 sheet（如“玩具”）。第 1 行是人员与分工（只抄“QA填写”这类固定说明，人员名单不抄），第 2 行是表头，13 列：
  模块｜三端｜问题描述｜截图｜改法｜类型｜职能｜严重程度｜单子状态｜单号｜单子状态（自动）｜备注｜提出人
- 类型：bug / 需求（小写 bug）。严重程度：阻塞 / 严重 / 一般。三端：all / 手柄 / 移动端。单子状态：未提单（新导出）。
- 主题：这个玩法。导玩家为这个玩法走过的路径上碰到的问题（看 `activity`、`event_title`、界面路径），包括玩法要用到的通用系统（如活动要求在拍照模式里完成写生）；和这个玩法无关的另一段游玩，列在汇报里，建议另导到对应的表。
- 适合版本验收场次（`acceptance` 为真，`acceptance_target` 就是玩法名，按它选 sheet）。
