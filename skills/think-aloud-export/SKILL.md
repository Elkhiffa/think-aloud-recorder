# Think Aloud 跑测问题导出到 POPO 表格

记录者跑测（日常跑测、版本验收）时边玩边说，单场整理（think-aloud-judgments）已经把一场整理成判断实例：问题类型、是否 bug、陈述、原话、所指时刻、界面。这个 skill 只做最后一步：**按团队公共表的格式填表**。省掉的是人工填表的时间，判断本身不重做。

## 需要什么

- 软件目录（`agent_cli.py` 和 `runtime\python.exe` 在这里）和资料库路径：从「复制导出指令」里拿；没有就问用户。下面 `PY` 指 `软件目录\runtime\python.exe`，命令都在软件目录下运行。
- 场次：一场（场次文件夹或编号）、几场，或“全部场次”。
- 公共表链接，可以带 sheet 名；不说 sheet 就取最新的那个（通常排在最前、名字带最近日期），版本验收场次优先取名字含验收对象的 sheet。
- 反馈人：第一次问用户怎么写（表里已有的写法，如“保杰”），记在自己的工作目录 `export-profile.json` 里，下次直接用。
- `popo-cli`：POPO 文档命令行（CodeMaker 和 popo-doc skill 自带）。没有就停下告诉用户，不要自己装。

工作目录 `WORK`：自己选一个新目录放截图、规格和过程记录，不要放进资料库或场次文件夹。

## 流程

1. **读公共表格式**（只读）：
   ```
   "$PY" -B -X utf8 "<本 skill 目录>\scripts\read_table.py" "<公共表链接>" --output "$WORK\sheets.json"
   "$PY" -B -X utf8 "<本 skill 目录>\scripts\read_table.py" "<公共表链接>" --sheet "<sheet 名>" --output "$WORK\format.json"
   ```
   `format.json` 给出表头行（有的表第 1 行是人员、第 2 行才是表头）、每列的表头、已用取值（`vocabulary`，有固定取值的列才有）、截图列（`images` > 0 或表头含“截图”）、列宽。
2. **定每列填什么**：逐列对照 [references/tables.md](references/tables.md) 的列用途表。认不出的列留空，写进汇报。列的取值**只能**用这张表 `vocabulary` 里已有的词（大小写、写法照抄，如 `BUG` 与 `bug` 不能混）。选中的 sheet 还没几行（比如月初新开的 sheet）时，用表头相同的相邻 sheet（`sheets.json` 里 `header` 一样的）再读一次，合并它们的取值。
3. **取行**（只读）：
   ```
   "$PY" -B -X utf8 agent_cli.py export-rows "$VAULT" --session <场次编号>   # 可重复；全部场次用 --all
   ```
   每条判断一行：`kind`、`problem`（四类问题或 bug）、`bug`（explicit 明说 / suspected 疑似）、`statement`、`quote`（原话，含已确认的转写修正）、`screen_path`（界面一级、二级…）、`frame_at`（截图时刻）、`event_title`、`activity`，以及场次的 `folder`、`acceptance`（版本验收）。
4. **筛行**：只要 `problem` 为真的行；再按表的主题筛（手柄跑测表只要手柄相关：走焦、焦点、键位、按键提示、手柄操作逻辑等，判断依据是陈述和原话，不靠猜）。同一现象在同一场被说了几次，合成一行。没导出的问题记下原因（与表主题无关 / 观察类 / 合并到第几行），汇报时给出条数和几条例子。
5. **写每一行**（细则见 tables.md）：
   - 问题描述：仿照表里已有的写法，一句“界面 + 现象”，像 bug 单标题，不写分析过程、不写“记录者说”。
   - 类别/类型：明说的 bug → 表里的 BUG 词；其余 → 表里的优化/需求词。疑似 bug 也填 BUG 词，备注写“疑似 bug，待确认”。
   - 问题类型、优先级/严重程度、三端、职能：从这张表已有取值里选；拿不准就留空，汇报里列出“需要你定的格子”。
   - 反馈人/提出人：反馈人；区服默认表里最多的那个（如“国服”）；状态填表里“还没处理”的那个词（如“未处理”“未提单”，表里没有就留空）；跟进人、单号、QA、单子状态（自动）留空。
   - 备注：`原话：“…”｜场次 10-19 22:40 · 01:35`（场次日期时刻 + 所指时刻），方便回去看录像；疑似 bug 的说明也写这里。
6. **截图**：每行截所指时刻一张（`frame_at`）；同一行若陈述里有对照时刻或第二个关键画面，再截一张。
   ```
   "$PY" -B -X utf8 agent_cli.py frame "<场次 folder>" --at <秒> --output "$WORK\frames\<场次编号>-<实例编号>.jpg"
   ```
   截到的图要看一眼：画面不是陈述说的那个界面就换时刻或不放，不要放错图。没有真正看到图（工具只返回了一行文字）不算看过。表里截图列放不下的图，填进 `more_images`，链接会追加到备注列。
7. **建新表**：把以上整理成规格 `$WORK\spec.json`（格式见 `scripts\write_sheet.py` 开头的说明）：
   - `title`：`<公共表标题>·导出·<反馈人>·<日期>`；`sheet_name`：公共表的 sheet 名；
   - `header_rows`：表头行及其上方各行，按 `format.json` 原样抄；`col_widths`：照抄；
   - `dropdowns`：有 `vocabulary` 的列（问题类型、优先级、类别、状态等）给出取值；
   - `rows`：按场次时间、所指时刻排序。
   ```
   "$PY" -B -X utf8 "<本 skill 目录>\scripts\write_sheet.py" "$WORK\spec.json"
   ```
   新表建在用户本人的云空间根目录。写到一半失败时，修好规格后用 `--doc <docId>` 写回同一张表，不要再建一张。
8. **汇报**：新表链接；导出了几行（bug 几条、体验问题几条，来自哪几场）；没导出的条数和原因；需要用户定的格子；截图失败项。最后一句：“看过没问题后，请自己复制到公共表。”

## 边界

- 公共表只读：不写、不改、不删任何别人的表；新表只建在用户本人云空间。
- 不提单，不填单号、QA、跟进人。
- 只用单场整理已有的判断；不重新整理，不改场次结果、议题表或资料库里的任何文件。
- 版本验收场次照常导出（它只是不参与跨场次分析）。
- POPO 返回权限或授权错误时停下，告诉用户在 POPO 里确认授权，不要反复重试。
