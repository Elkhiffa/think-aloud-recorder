# 界面编号怎么定

`screen` 是判断所指那一刻所在界面的编号，按“界面组”命名。跨场次靠它把同一个界面的问题聚到一起，所以同一个界面在各场必须用同一个编号：**目录里有的，照抄目录编号**；没有的，按下面的规则命名并标 `screen_proposed: true`。

- **什么是一组界面**：画面出现和上一屏不同的一级或二级页签，就是进入了新的一组。组名取上一屏打开它时用的入口名（按钮、菜单项或按键提示上的文字）；新界面有自己的标题且和入口名不同时，组名写 `入口名（标题）`。编号写 `组名/一级页签/二级页签`，没有的层级省略，上一屏的路径不带进来。入口名和标题不一致本身就是导航定位的线索，两者都要保留。入口只是“前往”“查看”这类动作按钮时，组名用标题，按钮写进 `route`。
  - 例：在 `培养/装备` 点“流派指引”，新界面没有单独标题、顶部页签是“流派推荐 / 流派挑战”，写 `流派指引/流派推荐`。
  - 例：主菜单点“活动”磁贴，打开标题为“燕语江湖”的界面并停在“活动”页签，写 `活动（燕语江湖）/活动`。
- **交用户确认的情况**：入口没有文字（无字图标、缩略图、快捷键）且新界面也没有标题，或入口文字随状态变化。按记录者口述或系统通用名暂定组名，标 `screen_proposed: true`，`refers_to.note` 写明“入口与界面无稳定文字，组名待用户确认”。
- **侧窗、弹窗、详情**归在打开它的那一组下面：`入口名/页签/侧窗标题`。背包写 `背包/分类`。
- **没有标题、只有页签的面板**：组名取玩家这次打开它用的入口（图标旁的文字、NPC 对话选项、任务按钮的文字），后面接页签；入口也没有文字时，按上一条“交用户确认”处理。教学或任务自动打开的，入口写成触发它的那一步（如 `任务·前往战备`），标 `screen_proposed: true`。
- **系统自动弹出的窗口**（更新提示、断线重连、退回登录确认）不属于任何一组：组名取弹窗第一行文字或它的用途（如 `资源更新提示`），标 `screen_proposed: true`，`route` 写弹出前所在的界面。
- **同一组界面有多个入口**时只用一个编号：目录里有的照抄；没有的按本次实际入口命名。实际从哪个入口进来写在 `route` 里，跨场次由目录把其他写法统一为别名。
- **层级注释**：知道某层是页签还是模块入口时，在 `refers_to.note` 里写带注释的路径（例：`培养/装备〔页签〕/装备〔模块入口〕/槽位调平〔页签〕`）。
- **`route`** 按顺序记录经过的界面组，每跳到新的一组记一步；同一组里切页签、开侧窗不算一步。进入玩法后的战斗、HUD 判断，知道是从哪个入口进来的，也把入口写进 `route`（如 `武林录/挑战 -> 大散关`）。
- **不对应具体界面**时 `screen` 为 `null`，用 `screen_context` 说明：`hud`（HUD、战斗、大世界）、`multi_screen`（跨多个界面的总体评价）、`outside_game`（游戏外窗口）、`unknown`。弹窗、菜单、结算都按界面记。
- **`elements`** 写判断针对的元素在画面上的文字，没有就空。
