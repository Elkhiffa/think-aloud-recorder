# 案例

每个案例标明它说明 SKILL.md 里的哪条原则。案例来自《燕云十六声》的真实场次，用来帮你理解原则；遇到不一样的情况，按原则判断，不要套案例的字面。

## 什么算问题：看后果

- **随口一问，问完照常操作** → 不记。“我是不是没带那个外观啊”，随后看了一眼装备栏继续玩，之后没再提。
- **问了，当场点开就懂** → 观察。看到武器卡片下一条没有说明的白条，点开「查看详情」才知道是耐久，之后照常操作。陈述写他靠什么弄懂的。注意：如果同一个白条后面还让他误判，就不是观察了。
- **反复出现的情绪** → 合成一条价值判断。每次搜刮都说“全是破烂”“好烂”，单句只是情绪，合起来是“搜刮产出的价值低”，`kind` 为 `value`，`said` 放全部原话。

## 类型：最早断掉的那一环

- **未察觉**：他说“看不出拍到的有没有红色”，截图里照片左下角其实有颜色标签。信息给了，他没注意到 → `unnoticed`，原因是标签不显眼、没有引导，落地方 `visual_hierarchy`。不要写成“没有提示”。
- **未察觉（办法藏在设置里）**：特殊技和处决的按键优先级冲突，设置里其实有对应开关，他不知道。办法存在却没被发现 → `unnoticed`，陈述写明开关在哪，落地方通常是 `tutorial` 或 `visual_hierarchy`。
- **理解错 vs 目标不明**：他问“什么叫凌虚冲制”。先看任务引导和机制说明里有没有写怎么触发：写了而他没看到 → 未察觉；写了但看不懂 → 理解错；完全没写、他不知道这一步要干嘛 → 目标不明。
- **找不到（信息不在眼前）**：所问的信息当时界面上看不到，要靠记忆或回头去查，并且因此停下来翻找 → `not_found`，陈述写清当时界面上有没有这项信息、之前在哪里显示过。
- **最早的一环优先**：没注意到教学提示，于是对规则理解错、打了几次都失败 → 标 `unnoticed`，后面的理解错和失败写进陈述作为后果。

## bug：以记录者的判断为准

- **明说**：“什么神秘的社交bug”（转写有误，疑为“走焦bug”），声望图鉴焦点从第 1 个跳到第 4 个 → `bug: explicit`。
- **用实现问题的说法**：“这个时间哦，是和这个重叠的”，局内地图上撤离点倒计时和任务面板叠在一起 → 用了“重叠”这类落地实现的说法，按 `explicit` 记。
- **疑似**：他只问“我的焦点为什么初始在右边？”，画面显示打开木桶时焦点在右栏、几秒后打开货物车又在左栏，同一操作结果前后不一致 → `bug: suspected`，类型照常判（如 `hard_to_execute`）。

## 一条实例一个所指

- **合并**：整场反复说“试用特效又没了”“怎么又变成默认款”“这样算装上了吗”，都是试用特效的装备状态和实际效果对不上 → 一条，陈述写清第一次怎样、后来怎样、最后是否弄清。
- **拆开**：试用列表铺出全部奇术（列表太长、找不到自己的）和试用状态不生效，对象相同、原因不同 → 两条。
- **一句话两个所指**：“模板太少了……两张图的时候效果非常烂”，其中模板少是因为没看到版式选项（未察觉），出图效果差是对拼图本身的评价（价值判断）→ 两条。

## 所指的时刻

- **隐含回顾**：在新界面里说“上一个界面那个按钮我都没注意到” → `retrospective`，`screen` 填上一个界面，类型 `unnoticed`。
- **比较，问题在当前界面**：“这里要手动点最大，刚才那个弹窗不用” → 主所指是当前界面（`same_time`），刚才的弹窗放 `compare_to`。
- **之前的游玩**：“又是前几天那个卡住的问题” → `earlier_session`，note 写清所指。

## 陈述的写法

按“要旨 → 想做什么 → 遇到什么 → 后果 → 画面原因 → 为什么算问题”写。示例：

> 打开容器拾取时，初始焦点时左时右，要先把焦点挪回左栏才能拾取。他在渡尘墟（搜刮撤离玩法）里打开木桶想捡东西，焦点却落在右栏自己的背包上，他问“我的焦点为什么初始在右边？”。他手动把焦点移回左栏才拿到物品；几秒后打开货物车，焦点又在左栏。同一个“打开容器”操作，焦点落点不一致，用手柄每次都可能多一步，而拾取是这个玩法最频繁的操作。

对照旧写法的毛病：把六七句原话按时间串起来、结尾写“见同场另一条”、写“第 2071 秒”——读者既看不出发生了什么，也拿不到那条“另一条”。

## 活动标题

写明从哪个系统或玩法进入：“武林录·镇守挑战：反复刷镇关吼”“首领战（从太平武墓进入）”。跨场次按系统、玩法筛选时，靠它找到战斗、HUD、结算这些界面的来源。
