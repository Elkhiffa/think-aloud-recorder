# 案例

每个案例标明它说明 SKILL.md 里的哪条原则。带场次编号的取自《燕云十六声》的真实场次，没带的是示意。案例用来帮你理解原则；遇到不一样的情况，按原则判断，不要套案例的字面。

## 什么算问题

- **随口一问，不影响手上的事** → 不记（示意）。打怪间隙问“这个图标是新加的吗”，没人回答，他继续打，之后没再提，这个图标也不影响他打怪。
- **问了，点开才懂** → 问题，`unclear_meaning`，强度 1（示意）。看到卡片下一条没有说明的白条，点开详情才知道是耐久，之后照常操作。记录者知道该点开，一般玩家未必。陈述写靠什么弄懂的。
- **最后说“没啥问题”也算** → 问题，`wrong_expectation`。提示写「进度将会互换」，互换后两本心法的突破重数都清零，返还成心得，要自己一重重点回去。记录者点完说“没啥问题”。数量没损失，但互换的主体是进度，结果却是材料，这不是玩家预期的（de52b1 i07）。
- **靠推断才弄懂用途** → 问题，`missing_info`。问“这个功能是用来干啥的？”，对照别的页签约两分半才想通。界面直接摆出功能，没先说什么时候用、为了什么（换流派）。设计上应该先给“要不要用”的信息，再展开操作和规则（de52b1 i05）。
- **自问自答也可能是在心算** → 问题，`missing_info`。补心力时问“这是多少？”，自答“600”。操作记录显示按住 RT 加到 12 份，又退回 10 份；面板不显示补完是多少，要自己算（16303d）。
- **同一件事反复试** → 问题。问“这算是贴上去了吗？”，又反复摄取、调整五次，才出现镶接提示；最后成功不改变判断（632f29 i07）。
- **设计师判断，没有受阻也算** → 问题，`evidence_source: expert`。伙伴同游里一个状态叫“人瘾”，他看到下方日志写“身体不适”才知道是病，说“要是我没看到下面这一句……我还以为这个人（瘾）也是包装的一部分”。他自己没误解，但判断状态名单看会被当成装扮文字 → `unclear_meaning`，落地方 `copy`（b9777c i01）。
- **指不出设计缺口** → 观察。戏叶同乐无人质疑也翻牌，他按别的唬牌玩法的习惯以为只有质疑才翻，连问几句后翻开说明读到了规则。问“本该有什么”：规则在流程中给了、也读得懂，答不出缺了什么，疑惑来自他带进来的习惯（0c6bf7 i12）。对比上面“问了，点开才懂”：白条本身没有任何说明，缺的是标签，那是表意不明。
- **游戏规则有意的限制** → 不算问题（示意）。技能冷却中按不出来、体力耗尽时不能闪避。
- **反复出现的情绪** → 合成一条体验与价值（示意）。每次开箱都说“全是破烂”，单句只是情绪，合起来是“开箱产出的价值低”，`design_defect` 为 `value`（体验与价值），`said` 放全部原话。单独一句“这刷到啥时候是个头呢”（447ab7 i28）针对的是反复刷的节奏，也归这一类。

## 类型：游戏的哪个设计有缺陷

- **视觉层级（没注意到）**：在地图上来回找了很久，最后说“哦，这儿呢”“这个任务图标挡住了”——要找的图标被同位置的另一个任务图标盖住，同位置多个标记没有错开 → `visual_hierarchy`，表象 `unnoticed`（4f5242 i22）。回顾式的同样算：离开衣柜后回想“这为什么我刚才没看到呢？”，切换页签后最上面的新物品不在视野内 → `visual_hierarchy`，`retrospective`（f2d630 i04）。
- **表现错误**（示意）：道具详情的标题和右上角图标重叠，他说“这个字儿都重叠了呀”，没有因此读错 → `display_error`，带 bug，仍算问题。
- **信息缺失（导航）**：问“那这里是从啥进的？”，回主菜单才确认这个商店是从“不肝”磁贴进入的，又问“我刚才在哪儿呢？”——界面没告诉他在哪、从哪来 → `missing_info`，表象 `not_found`（c68962 i21）。
- **表意不明和信息缺失，看他问的东西在不在眼前**（示意）：血条旁有个 0/12，他问“这个数是什么”，数字在画面上却读不懂 → `unclear_meaning`。他问“这个技能要耗多少能量”，界面上根本没写 → `missing_info`。两者的改法都可能是补说明，但类型不同。
- **状态给了明确读法，实际不符** → `wrong_expectation`。缺材料的配方整张灰掉，读作没解锁，买完材料才说“我还以为是我没解锁呢”（de52b1 i16）。
- **读不出该按什么理解** → `unclear_meaning`。鲁班锁的提示画着四向箭头，又写“上下移动”，记录者不知道操作方式到底是什么（632f29 i04）。
- **提醒不该出现** → `value`。15 公里外的新探游一直占着任务栏，问题不在显不显眼，而在这时不该提醒（632f29 i15）。
- **还没想做就收到失败提示** → 不是 `blocked`。坐船路过触发了事件，页面写未完成；记录者没想参与，问题是这个提示不该发给没打算参与的玩家（`value`）。想补做时查不到规则是另一条 `missing_info`（632f29 i16、i17）。
- **同样卡在对调装备，缺陷不同**（示意）：他想把两个槽位的装备对调，找了半天。
  - 能做到，只是要先卸下再装上 → `hard_to_operate`。
  - 完全没有办法 → `missing_feature`。
  - 有对调按钮，就在眼前，他没注意到 → `visual_hierarchy`。
- **一致性归预期传达有误**（示意）：这个界面的返回键在右下，别的界面都在左下，他两次按到别的按钮 → `wrong_expectation`，相似功能用了不同设计。他只是说“这个按钮位置不太对”、没有按错，设计师判断也算。
- **可能是有意设计、游戏没传达过别的预期** → `value`。游船离岸已经很远，他说“已经走了很远”，岸边两人还在说话。这可能是有意让玩家不用停留也能听完对话；游戏没在别处给过“走远就听不到”的预期，所以记成他在这个场景下的判断，不记预期传达有误（632f29 i19）。
- **操作困难**：“这里又按错了，又得退出场景”（447ab7 i29）；“在频繁的切刀和卸式的过程中，老是容易把道具按错”（b3fadd i07）；在装备回收里逐件筛选时说“哎，搞这么麻烦”（e5f804 i01）→ `hard_to_operate`。陈述要写清难在哪或麻烦在哪几步，单句“好麻烦”而看不出对象的，按所指不明处理。

## bug：以记录者的判断为准

- **他认为是 bug**：领取奖励后在弹窗里对“使用”连按 A 三十多次没反应，改用鼠标，说“估计是什么手柄独占的bug”→ `bug: explicit`，类型照常判（`blocked`）（7ee3c1 i24）。
- **表现异常，没用技术词**：跟随任务时右侧提示和画面元素叠在一起，他说“重叠在一起”→ `bug: explicit`（4f5242，补记后编号以最终结果为准）。
- **行为异常，他明确说出它没做到该做的**：同一条突破提醒，菜单里的「可突破」看过就消了，模式选择界面「单人模式」旁的红点还亮着，他说“红点只消了一个路径，另外一个路径的没有消”→ `bug: explicit`，类型照常判（`wrong_expectation`）（b6c191 i07）。
- **可能是有意设计，他没断言出错**：单人模式退出玩法后队伍还在，他问“我不是在单人吗？”，随后自己解释成玩法会保留队伍 → 不标 bug，按类型记。用户事后批注判它是 bug（单人保留队伍没有意义），按“用户的定性等同原话”改为明说（f2d630 i30）。
- **他自己也拿不准**（示意）：“这算 bug 吗？可能也不算吧”→ `bug: suspected`。
- **战斗里没躲开**：首领连招间隙按了闪避仍被打中，他问“这不是闪了吗？为什么没有闪到呢？”，随后又问“为啥早了？”→ `bug: suspected`，难度和时机相关，主观判断不足以认定 bug（b3fadd i09）。只说“哎，没闪出来”、画面显示按键晚于命中 → 不标（68f486 i02）。
- **手柄做不到、鼠标可以**：“我没法用手柄点开”→ `bug: suspected`，可能是手柄路径没做，也可能是焦点失灵（4858ba i35）。
- **用户说明是有意设计**：任务进度在离开区域后退回，他问“为什么还要再读？”；用户说明这类任务按设计会在离开一段时间后重置 → 不标 bug，按设计缺陷判（a3ad38 i18）。
- **他没说，画面显示前后不一致**（示意）：同一个“打开背包”操作，焦点一次落在装备栏、一次落在道具栏 → `bug: suspected`，陈述写看到了什么。

## 忘了目标

- **流程结束不回来源页面**：教学通关后经加载图被送回大世界，他转了一圈才说“哦对，我刚才是想把所有教学都看一遍”→ 记问题，`symptom: goal_unclear`，`missing_info`，陈述写清来路断在哪（7ab15c i28）。
- **自己选的长玩法**：打了 35 分钟别的玩法才说“我本来好像是来清红点的来着”，看不出游戏该负的责任 → 记 `observation`，留给跨场次看是否反复出现（f1d1e4 i47）。
- **不算**：被提示带去别处、回来接着做，说“我还没把这个看完呢”，没有忘了的信号 → 不记（7ab15c）。

## 一条实例一个所指

- **该合不该拆**：“自动滚动啊，感觉是前两天那个同款bug”说的是同一件事——头像列表自己在滚，他认为是之前遇到过的 bug。一句话、一个所指 → 一条实例（`bug: explicit`，note 写明他说以前遇到过），不要拆成“自动滚动”和“同款 bug”两条（7ee3c1 i39）。
- **合并**（示意）：整场反复说“特效又没了”“怎么又变成默认款”“这样算装上了吗”，都是试用特效的装备状态和实际效果对不上 → 一条，`refers_to` 取最能说明问题的那一刻，陈述写清第一次怎样、后来怎样、最后是否弄清。
- **拆开**（示意）：试用列表铺出全部条目（太长、找不到自己的）和试用状态不生效，对象相同、原因不同 → 两条。
- **所指不明**：看完一页设置回到上一页，说“嗯，好麻烦”，看不出指的是哪一项（f1d1e4 i34）→ 观察，`confidence: low`，note 以“待记录者确认：”开头，写出候选对象。

## 所指的时刻

- **比较，问题在当前界面**（示意）：“这里要手动点最大，刚才那个弹窗不用” → 主所指是当前界面（`same_time`），刚才的弹窗放 `compare_to`。
- **之前的游玩**：“感觉是前两天那个同款bug” → note 写明他说以前遇到过；整条指向之前的游玩时用 `earlier_session`。

## 陈述的写法

按“要旨 → 想做什么 → 遇到什么 → 后果 → 画面上的缺陷 → 为什么算问题”写。用上面地图那一例（4f5242 i22）示范：

> 地图上要找的活动图标被另一个任务图标完全盖住，他来回找了很久才发现。他想在地图上找到“五音启太平”的位置去接活动，在地图上反复拖动查看，最后说“哦，这儿呢”“这个任务图标挡住了”。截图显示两个图标落在同一坐标，“江南·五音传秘”的任务图标叠在上层，下面的活动图标一点都露不出来。同一位置有多个标记时没有错开或聚合提示，被盖住的那个等于不存在。

对照常见的毛病：把六七句原话按时间串起来、结尾写“见同场另一条”、写“第 2071 秒”——读者既看不出发生了什么，也拿不到那条“另一条”。

## 活动标题

写明从哪个系统或玩法进入：“武林录·镇守挑战：反复刷镇关吼”“首领战（从太平武墓进入）”。跨场次按系统、玩法筛选时，靠它找到战斗、HUD、结算这些界面的来源。
