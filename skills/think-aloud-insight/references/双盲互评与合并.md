# 按需：双盲互评与合并

默认只写一份报告。重要的报告，比如要发给组里的，用户可以要求走这一套，成本约为单写的三倍。2026-10-21 手柄试点按这一套做过。

## 为什么

- 两个 agent 互相看不到对方，各自独立写出的同一结论，可信度最高。只有一方写到的，可能是误判，也可能是另一方的盲区，标出来保留，不删。
- 单一评审会偏向自家写法：10-19 对比和 10-21 试点都出现过，两边评审各自认为“遗漏”的，正好是自家报告写了的。所以只采信两边一致的结论，分歧交给用户。

## 步骤

1. **盲写**：同一份简报，两个 agent（例如 Claude 和 Codex）各写一份，工作目录分开，互相不读对方的产出。
2. **互评**：每一方只评对方那份，不读自家的。评审说明直接用 [互评说明.md](互评说明.md)（调用时给出 `BRIEF`、`VAULT`、`REVIEW` 和被评报告），逐项评：
   1. 症结证据是否成立；
   2. 有没有合过头或拆过头（按设计规则判断）；
   3. 严重度宽严是否一致；
   4. 有没有遗漏；
   5. 抽查事实；
   6. 好不好读。

   最后给出最该改的三处。
3. **汇总**：主持方写一份“互评结论”：
   - 两份报告不约而同的结论；
   - 两位评审都认同的原则和事实错误，事实错误要亲自核对；
   - 有分歧、交用户判断的。

   用户裁定后，写进简报或做法说明。
4. **合并**：由一个 agent 把两份报告合成一份，按 [报告格式.md](报告格式.md) 写：
   - 每个问题标“共识”或“单方发现（仅 X，待复核）”；
   - 共识再分两档：两份都写进正文的，和一份写进正文、另一份只在附录候选里提到的；
   - 按两位评审都认同的原则拆分和改正；
   - 附录列出合并后每个问题来自原两份报告里的哪几条。
5. **写回与校验**：合并版走 SKILL.md B 部分第 11–14 步：写回议题树、写报告、`insight-validate`、过程记录。
