# 回看播放器按可用窗口适配 — 2026-09-27

上一轮的 900 × 540 最小目标仍受小的默认原生窗口和 212 px 操作卡片约束。
真实默认窗口的超宽画面因此仍然偏小。此次替换固定像素目标，处理这三个约束。

## 适配策略

- 原生回看窗口初始采用所在显示器工作区约 90% 宽、92% 高，保留桌面边缘，
  可自由移动、缩放并同时打开多个窗口。小屏仍受工作区及最小窗口尺寸约束。
- 自动分栏先给右侧留下可读空间（约 26% 可用宽度，上限 480 CSS px，
  同时满足现有文字和按钮的最小宽度），视频使用剩余宽度，受真实可用高度限制。
- 视频槽始终按源画面比例等比适配。没有固定 900 / 1290 px 上限；
  扩大窗口时画面继续扩大，手动拖动分隔线后的宽度仍由用户控制。
- 整段没有有效操作记录时，操作卡片压缩到 86 CSS px，保留缺失原因，
  不为不存在的按键或设备图留出大块空白。此规则按整段资料判断，
  不会因为某一时刻没有按键而让视频反复变大变小。切换回看筛选也不改变它。

设计参考 YouTube 官方对[窗口可用空间](https://support.google.com/youtube/answer/6052392?hl=en)
和[源视频比例](https://support.google.com/youtube/answer/6375112?co=GENIE.Platform%3DDesktop&hl=en)
的说明；侧栏宽度和操作卡片尺寸是本工具的具体设计，并非宣称复刻其实现。

## 验证

- Python 全量 527 项：524 通过、3 个预期的显式启用检查跳过。
- 真实 Edge 视频比例及窗口变化 14 组通过；生产操作回看 32 组通过。
- 2226 × 1120 浏览器视口：3440 × 1440 合成视频实际显示为
  1674 × 700.73，右栏 480，空操作卡片 86（均为 CSS px）。
  同一视口 16:9 视频为 1578.66 × 887.98，由可用高度限制。
- 保留源比例、独立滚动、手动分栏、元数据替换、窄屏上下布局、
  全屏、切回原画面；连续窗口变化无布局振荡。
- 显示器选择和工作区上限的检查覆盖普通屏、多屏及 3440 × 1440 超宽屏。
- 实机还发现 `webview.screens` 是惰性 `Proxy`，旧的 list/tuple 类型检查会
  直接采用固定尺寸。改为先取得屏幕列表，并用运行时实际的 `Proxy` 类型回归验证；
  主窗口关闭后，读取坐标失败也不会放弃已取得的屏幕尺寸。
