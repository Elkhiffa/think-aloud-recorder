# Think Aloud 0.9.0

三个窗口全部重新设计：主窗口改成 720×520 的录音机，设置改成一页表单，资料台的场次库改成表格加详情。分析改用两份正式 skill：单场整理 `think-aloud-judgments` 和跨场次分析 `think-aloud-insight`。开始和结束录制更快，录像真正开始时会响一声提示音。

## 主窗口

- 左侧是占满全高的录制块，写着游戏名和就绪状态。右侧一栏从上到下是游戏页签、上一场、“全部场次”和“洞察”两张卡；底部是记录方法和设置。
- “上一场”显示日期、名称、四类问题的比例条和计数，以及一句原话。状态依次是已保存、转写中、核对中、待整理。待整理时可以「复制整理指令」，粘贴给 Codex 或 Claude。
- 录制条件不满足时，录制块变灰，右栏顶部只写一条原因；「全部 N 项」列出所有原因。
- 三个窗口都去掉系统标题栏，由页面自己画标题区；拖动、贴边、四边改大小仍交给 Windows。标题区左上角是应用图标。
- 没在录制时，整个录制块都是“开始录制”按钮，下方的录制条件也能点；鼠标悬停时整块变深，按下更深。
- 切到游戏窗口时，记录器照旧暂停空闲时的录制条件检查（防 OBS 在锁屏时崩溃），但主页保留上次的检查结果，不再显示“录制条件尚未满足”；还没检查过时写“切回这里时检查录制条件”。点“开始录制”时仍会完整检查一遍。
- 视觉方向是浅暖纸色底，标题用宋体（随包提供 Noto Serif SC Bold），正文用更纱黑体 UI。红色只用于录制和回看播放头。目前只有浅色。

## 设置与首次使用

- 设置改为一页表单：一级页签“游戏 | 通用”，“游戏”下面每个游戏一个二级页签。没有修改时只显示“关闭”，有修改时显示“保存”。
- 设置 → 游戏最下方可以「删除这个游戏」。默认只删除软件里的设置，资料文件夹原样保留；勾选并输入游戏名后，资料文件夹会移到 Windows 回收站。
- 「记录方法」改为左右两栏：左边是怎么说和录完以后怎么整理，右边是四种说法的例子。首次设置的第一步也是这个排版。
- 「记录方法」和首次设置第一步新增「查看 skill 安装方法」，在浏览器打开仓库里的安装说明，不传任何本机信息。

## 资料台

- 场次库是一张按月分组的表格，列有日期、场次、开始、时长、问题数和四类比例、状态。可以搜索，可以按状态和问题类型筛选，可以按时间或问题数排序。
- 选中一场，右边显示详情：回看、复制整理指令、复制资料库路径；打开资料文件夹、重新整理、导出、原始录像和恢复云端任务收在「更多」里。还有四类问题各自的原话、这一场挂在哪些洞察下，以及可以跳到回看的体验事件。
- 场次名可以在详情里原地改名。
- 多选的筛选（问题类型、界面来源）选中后变黑，单选的页签选中后变白，各窗口统一。

## 录制与整理

- 开始录制改为等 OBS 的录制源真正激活再确认；确认后响一声约 0.2 秒的提示音，听到即可切回游戏。提示音会录进回放用的混音轨，不进入纯口述音轨。
- 结束录制的保存轮询更快；开始、结束和就绪检查都记录各阶段耗时。
- 场次列表不再等结果校验完才显示。还在核对的场次显示“核对中”，不会被误报为待整理。

## 分析 skill

- 单场整理 `think-aloud-judgments`：把一场录制整理成可追溯的判断实例。
- 跨场次分析 `think-aloud-insight`：维护议题树；并按用户确认的分析简报，自上而下写洞察报告，定位到游戏属性，按设计规则合并，用三问定严重度，报告校验会核对引用原话。
- **转写修正**：整理时认出的误转写（如“左交”→“走焦”），agent 用 `transcript-fix-propose` 提议，用户在对话里看过全部命中后确认。可以是全库规则（一个词一次确认，所有场次生效，个别处可排除），也可以是单处修正。逐字稿不改；确认后原话在转写原文旁多一份修正后的字，报告引用和 `insight-validate` 直接认它，已有整理结果不用重做。回看窗口里的确认入口以后做，读同一个文件。
- 单场整理截图 `frame` 默认 1280 宽，用 `.jpg`（约 170 KB，原来 1920 宽 PNG 约 2 MB，多个 agent 并行读图时会卡住）；看小字时加 `--width 1920`。skill 写明：读图没有实际返回图像，就不算看过。
- 写回议题树：`issues-update`、`issues-unlink` 支持 `--file` 批量处理，长中文说明从 UTF-8 文件读入，任何一条不对整批不写。
- 旧的 `think-aloud-preprocess` 由这两份 skill 取代，旧结果继续可读。安装方法见 [Skill 安装与更新](agent-integration.md#skill-安装与更新)。skill 不随软件更新，需要单独安装。

## 界面路径识别

- 情景轨道的文字识别保存文字框四个角点；每帧记下一到三级页签哪个亮着（顶部文本、横向文本、左侧图文、纯图标页签），以及主标题和侧窗标题。焦点位置这次不做。
- 判法按游戏分开：`layout_common.py` 是通用部分，`layout_yanyun.py` 是燕云的判法。界面目录的 `layout` 要写 `"recognizer": "yanyun"`，否则 `catalog-validate` 报错；没写 `layout` 时行为和以前一样。燕云的完整取值见 `docs/layouts/燕云十六声.json`。
- 提交单场结果时，自动核对界面编号里的页签段在核对时刻的画面上是否亮着，对不上就提醒 agent 再看一眼。
- 镜像库 26 场抽查：干净抽样 90 帧，报出 86 项、对 81 项；战斗、对话、过场 30 帧无误报。横向文本页签约 7.6% 的报告不是页签，已知误报类型写在 `docs/agent-integration.md`。
- 加了版式规则后，旧场次第一次 `context-build` 会整段重跑文字识别（旧轨道没有字框角点），一小时录像约 20–60 分钟。

## 修复

- 回看操作时间轴：活动带里的长按标签和长按底色下移了 1 像素，最小缩放时会越出自己的长按，压到下一次按键。已改正。
- 软件内更新和发布检查现在能识别随包的界面字体及其来源记录，不再把它们当作未授权文件拒收。
- 回看「最近操作」选「设备图」时，键盘和手柄图原本只露出最上面一条，要在面板里滚动才看得全。现在这一栏在设备图模式下加高、视频相应缩小约 9%，整张图按面板缩放；切回「最近按键」或收起后视频恢复原尺寸。这一栏的顶部左边是「最近按键 / 设备图 / 收起」切换，右边是设备选择（默认「自动切换」），不再单独写“最近操作”标题。设备名、“游戏在前台”和“最近 2 秒无操作”不再显示：设备图本身说明是哪种设备，前后台和空闲在操作时间轴里都有标记；采集中断等异常提示照常显示。窗口或分栏变窄时，这一栏至少保留顶部一行的宽度，先收窄原话区。
- 回看播放进度条加了浅色底，能看出整段长度。
- 主窗口“上一场”的进度：只有正在进行的一步铺满并带进度条，已完成的步骤收窄成标签加灰色对勾，还没到的收窄成标签加空条。
- 旧的 `think-aloud-preprocess` skill 标为已停用，即使被误装，agent 也会先看到“改用 judgments / insight”。
