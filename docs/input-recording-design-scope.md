# 操作记录与提前回看：已确认范围

2026-09-22。阶段：已获开发确认，正在完成生产接入与本地候选版验证。本文保留设计阶段判断；当前实现与真实设备验证边界见 `input-capture-validation.md`。

## 目标与已确认选择

将物理操作、视频中的系统反馈和口述放在同一播放时间上，支持观察未被说出来的反复尝试、停顿和操作顺序。操作数据本身不证明游戏接收了输入，也不自动证明玩家意图或设计缺陷。

- Windows 键盘、鼠标、Xbox 手柄、PS5 DualSense。设备支持须实机验证；图标外观不等于设备兼容证明。
- 仅指定程序/窗口录制可启用操作记录。全屏录制时禁用该选项，并在向导说明切换录制范围的前提。
- 仅在实际目标程序/窗口位于前台时采集，过滤必须在持久化前生效。切到其他程序时暂停操作采集，视频按既有录制规则继续。返回后重新建立状态，缺口不得补成按下、松开或没有操作。
- 操作采集随每次录制启停，选择随预设保存。不存在录制时的全局键盘演示或永久监听需求。
- 支持录制过程中热切键鼠与手柄，常态按单一主动设备呈现。自动模式按最近明确操作切换，空闲保留上次设备；鼠标微动或摇杆漂移不抢占。少见的重叠输入仍保留原始记录与时间轴，不强制排他。
- 视频整理就绪即可打开回看，转写无需同时完成。
- 转写尚未完成时，右侧原话页签禁用，显示“转写中”。完成后恢复“原话”，同步到当前视频进度；不改变播放位置、播放/暂停状态、倍速或用户当前选择的页签。

## 呈现合同

| 区域 | 内容 | 状态与交互 |
|---|---|---|
| 视频下方 | 当前操作 / 设备图 / 收起 | 当前操作默认；组合键只代表真正重叠的输入；设备图随来源或手动选择键鼠、Xbox、DualSense |
| 右侧 | 操作 / 原话 | 独立于底部切换；点击键位条定位视频；操作内容区滚轮调整播放进度，时间刻度区滚轮调整时间轴缩放 |
| 操作时间轴 | 视频右侧区域内部，左起纵向时间刻度、固定宽度原话轨、紧凑键位区 | 时间自上而下等比例，条的起止和高度对应实际时间；键条占用最靠左的空闲位置，不为每个键固定独立轨 |
| 原话条 | 在原话轨内显示图标与区别于按键的颜色，高度对应持续时间 | hover 显示全文；点击固定文本卡，点击软件其它位置或 Escape 关闭；仅保留时间、正文及关闭按钮，不显示“已固定”或定位入口 |
| 图素 | 统一圆角黑底白字键帽，鼠标、左右摇杆及方向箭头 | 活动态使用现有暖红；保留设备标签、方向、轴幅度及扳机深度；可读名称与键盘操作 |
| 数据缺口 | 切出目标、设备断开、采集异常 | 与正常无操作、未启用、旧场次无数据分开表达；不中断或损坏视频 |

底部模式切换及自动设备切换不让左侧视频跳动。保持视频源比例，列表在自身区域内滚动。操作状态由视频播放位置重建，向前/向后拖动到长按中间都得到一致状态。重转写更新文本，不重写原始操作事实。

用户已明确替换早先按事件分行的方案：不对临近按键人为分组来判定同时按下，是否重叠由真实时间区间直接表达。紧凑排列不改变时间比例，长按条保持位置到结束，之后其它键可以复用该位置。整个时间轴仍在视频右侧，不移动视频区；其中原话轨不会横跨键位区。

## 已确认的高频输入固定轨

用户提出鼠标、WASD、左/右摇杆等高频输入值得固定纵向轴；在对照原型后回复“可以的。先出视觉稿吧”，现按固定方向轨继续视觉设计。原型暂保留两种对照：

- 紧凑：时间 / 原话 / 全部键位按区间占用紧凑排列。
- 固定方向轨：时间 / 原话 / 方向输入（WASD、左摇杆）/ 指向输入（鼠标移动、右摇杆）/ 其它按键紧凑排列。

鼠标按钮、摇杆按下仍属于其它按键。保留实际设备/输入图标，不据物理按键推断游戏实际语义；这次不加入逐游戏自定义动作映射。比较持续方向是否更易读取、空闲留白、按键区剩余宽度，以及键鼠与手柄热切后的位置稳定性。

2026-09-22 视觉评审追加：光标在时间刻度右侧内容区时，滚轮前后调整播放进度；光标在纵向时间刻度区时，滚轮快速调整时间轴缩放。实现建议以指针所在时间为缩放中心，调整进度时保持原播放/暂停状态；这两个细节为设计默认，并非额外用户确认。原话浮层不再显示定位按钮和“已固定”状态字样。最新窗口视觉稿见 design/input-review-v1；当前交互原型尚未同步这次滚轮与浮层修改，不能据视觉稿宣称功能已实现。

## 已核对的实现约束

现有程序只保存 OBS 返回的窗口标识，没有独立的前台进程过滤。现有场次的 started 时间早于 OBS 启动确认，不是精确视频零点。现有回看依赖逐字稿文件，句级 timeupdate 同步不能直接证明短按展示准确。桌面和离线 HTML 共用渲染入口，操作数据及状态均须同时接入。

Input Overlay 是采集候选；其 WebSocket 输出不能替代本项目的时间校准、数据落盘、缺口记录和回放重建。先验证版本兼容、实际手柄、焦点过滤、快速按键及长时漂移，再决定正式接入方式。

## 当前原型与下一阶段

原型位于 docs/prototypes/input-review，使用 32 秒合成视频和预制事件，不采集电脑输入、不连接 OBS、不进行云端转写。“模拟转写完成”等演示控制和产品界面分开，不能将其视为真实采集或转写验证。

验收原型：组合与长按、切出程序缺口、Xbox、DualSense、暂停/播放/倍速中更新转写、跨视图同步、列表独立滚动、两种主题及较窄桌面窗口。

设计阶段安排：原型评审 → 隔离采集验证 → 生产预设/场次/回看/离线导出接入与回归。原型只作历史设计证据，不用于证明生产行为。当前未改用户安装目录，未发布 Release。

## 开发确认后的补充

- 生产实现采用固定方向轨布局，不保留原型的两方案切换。时间轴按同一时间比例及列网格布局。
- 资料库路径复制按 2026-09-22 后续反馈移至顶部片段信息旁，不遮挡视频；回看页没有返回箭头。菜单仍提供场次、视频、逐字稿路径。
- 片段名独立于预设／游戏名，可在主列表及桌面回看页编辑；标题优先显示片段名，游戏名作为次级信息。不会改动文件夹名。
- 使用 Windows Raw Input 和随软件携带的 SDL2，避免要求用户额外安装全局 OBS 插件。原始操作与转写分别存储，独立恢复。
- 前台权限和 OBS 时钟有无法确认的部分时，停止相关输入或标注缺口；不猜测操作及其与视频的对应时间。设备实测、事件精度与代码／合成测试分别记录。
- 时间刻度与空白区支持单击定位；时间轴支持按住左键纵向拖动调整视频进度。原话条单击固定文本，拖动调整进度；手动定位保持播放／暂停和倍速，暂停时间轴自动跟随，避免坐标跟着指针跳动，原有「恢复跟随」可恢复。
