# OBS 输出查询崩溃：修复范围与证据

2026-09-23 的隔离测试在两次合成录像停止、视频同步校验完成后，于退出检查时触发 OBS 32.2.2 崩溃。崩溃线程的 PE 导出地址对应 `obs_enum_outputs` → obs-websocket 回调 → `obs_output_get_width`；不是录制、转写或操作采集线程。

上游 [obs-websocket #1344](https://github.com/obsproject/obs-websocket/issues/1344) 记录了相同触发链：`SetVideoSettings` 重置视频核心后，闲置虚拟摄像头输出可能保留旧视频指针，随后 `GetOutputList` 枚举宽高触发访问异常。该问题的诊断与本次栈一致；本次没有用调试器直接验证具体失效指针。

## 退出路径

不再发送 `GetOutputList`。改为分别要求录制、推流、回放缓冲、虚拟摄像头的状态明确为未活动。仅回放缓冲的 604（未配置）视为该输出不存在；其他错误、缺失状态或活动输出均保留进程。身份、创建时间、父进程、实际 WebSocket 对端、Experience 配置和场景检查保持有效。

这四个标准状态不能证明自定义输出已经停止，因此额外检查进程是否仍处于随软件提供的普通 OBS 环境：portable 启动参数、未设置外部插件路径、与进程启动时间匹配的完整启动日志、已加载插件名称/实际映射位置/锁定 SHA256、插件目录清单、脚本加载历史与配置，以及硬件输出模块和未知插件配置。无法确认或发现额外插件、脚本、AJA/DeckLink 输出模块时，返回 `custom_outputs_unverified`，不发送关闭请求，也不强制退出。

这是对用户正常改装 OBS 的保守检查，不是抵御本机恶意篡改日志和运行时锁文件的安全边界。缺失日志、运行时锁文件、读取权限或增加插件配置可能使自动退出有意保持保守；没有降级到危险的输出清单查询，也没有安装 OBS 插件或禁用用户扩展。

初始连接的重试握手原来使用 2 秒超时，成功后仍将这个短超时留给后续场景初始化；直接连接已有 OBS 则使用 8 秒。现已统一：重试仍最多 45 次、每次握手 2 秒；确认就绪后通过底层 WebSocket 的 `settimeout(8)` 恢复正常请求超时，无需再创建连接。针对性测试覆盖握手截止时间、正常请求截止时间和重试次数上限。
