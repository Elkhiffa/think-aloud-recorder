# 画面变化候选：本地试验版

这一步先机械检查录像，再让外部 agent 结合原话和操作理解过程。它不会调用模型、上传素材、改写场次、生成体验事件或覆盖已有分析；也没有挂到每次录制后的自动任务里。

## 使用

使用带 PyAV、NumPy 的软件运行环境。在安装包中，接口位于 `app/agent_cli.py`；从源码运行时应使用当前源码对应的环境。以下路径是示例，输出必须放在资料库之外的**新目录**。

```powershell
$python = 'D:\Think Aloud\app\runtime\python.exe'
$cli = 'D:\Think Aloud\app\agent_cli.py'
& $python $cli visual-nodes 'D:\think-aloud-database\场次\某个场次' --output 'D:\Think Aloud Development\evidence\某次检查' --max-images 120
```

默认检查整场，`--start 50 --end 85` 可先验证一段。会逐帧解码所选范围，不是每隔几秒给模型一张图。检测使用最长边 320 像素的画面；图片输出最长边 960 像素。低分辨率检测可能漏掉很小的文字或颜色态变化，需要用真实录像检验阈值，不能承诺语义完整。

结果为 `index.json`、`images/` 和 `review.html`。直接打开 HTML 可以检查候选图；若浏览器不允许它播放原视频，可运行仅在本机监听的检查页服务：

```powershell
& $python $cli visual-review 'D:\Think Aloud Development\evidence\某次检查\index.json'
```

打开返回的本机 URL；在终端按 Ctrl+C 结束。服务只提供该检查页、列入索引的图片和绑定的一个视频，支持定位播放，不提供目录浏览。URL 含随机访问路径。页面有原话和游戏截图，是私人工作材料，不能直接加入公开仓库或安装包。

## 检测和预算

- 使用相邻帧变化、相对参考画面的累积变化，以及网格内局部变化共同找候选。保留实际显示时间戳，不使用帧序号除以帧率推算。
- 连续动画/镜头活动合成 `motion` 区间；短变化返回旧画面保留为 `transient`，A→B→A 的再次出现不会全局去重。局部变化须满足突变、严格稳定和新近发生才升为主要候选，可以与连续运动区间重叠。更弱的变化保留在各节点的 `motion_observations` 中，默认不单独配图，需要时按时间补看；检查页有折叠列表。弱观察的独立限额也是 4000，遗漏会披露。
- 稳定段保留 `context` 作为前后文。`change` 只表示像素变化，不能直接叫“打开背包”或推断玩家目标。区域框只是机械差分区域。
- 默认最多选择 120 个配图时间，可设置 1–500；优先给变化与首尾上下文分配代表图，再给运动段和其他上下文配图，最后补前后图。同级候选超出预算时按时间均匀分配。同图文件可以复用，各次出现的时间不会丢掉。
- 配图达到预算不会删除候选。`unpictured_nodes` 表示无图候选；每个帧引用的 `path: null` 表示未配图。节点索引默认上限 4000，超出时另报 `node_index_complete: false` 和遗漏范围，需分段重跑。
- `coverage.complete` 只描述所选范围内视频画面的检查情况；它不是界面流程召回率，更不是体验目标覆盖率。请求范围、实际显示范围、首尾无画面的缺口分别保留，哪怕不到 0.1 秒也披露。还需检查 `node_index_complete`、配图缺口和原片。截取范围落在两帧之间时，保留跨越起点的前一帧，图片仍使用其原始时间戳。
- 视频须已保存，录制中的场次拒绝提取。逐字稿可暂缺。原话、说话者身份和操作同步沿用现有证据接口；原始输入偏移只应用一次。操作摘要有数量上限，完整操作仍需通过现有 `evidence` 按区间读取。
- 检测与截图各解码一遍，限制为两个解码线程；不会启动 OBS。缩小画面发生在解码之后，长片仍有本地 CPU 和磁盘成本。此版没有硬件加速或后台自动重试。

## Agent 按需读取

```powershell
& $python $cli visual-read 'D:\Think Aloud Development\evidence\某次检查\index.json' --offset 0 --limit 30
& $python $cli visual-read 'D:\Think Aloud Development\evidence\某次检查\index.json' --start 50 --end 85 --limit 30
```

索引可分页，每次最多 100 个候选，返回图片绝对路径、实际时间、原话引用和有限操作摘要。读取时检查素材 revision，素材/转写/同步变化后拒绝使用旧索引。revision 沿用原接口的文件大小、修改时间和相关设置指纹，不是内容签名。

建议 agent 先读小批节点索引，根据前后连续性选择图片，遇到遗漏、长 motion 区间或证据矛盾时再回看该范围。不要一次把全部图片都传给模型。需要更多图时可缩小时间范围再提取到新目录。

体验目标与问题的输出格式仍保持 v1。Agent 应先结合整场节点与全部原话，还原主要目标、尝试、转折和结果，允许“目标未明”；然后从事件中分析阻碍和问题。正常过程与无原话区间也属于覆盖范围。区分画面观察、原话明确表达和目标推测，机械节点的数量不等于体验事件的数量。

重做既有分析时，先备份上一轮评估报告，再通过 `reprocess --worker ... --reason ...` 领取：接口备份并校验旧结果，保留旧结果可读，直到新结果提交成功。只换方法不改素材 revision；对比应绑定相同场次与素材版本。具体方法见源码 `skills/think-aloud-preprocess` 与 [外部接口](agent-integration.md)。

## 检验方法

至少比较局部 UI 连续操作、短弹窗返回、动态游戏镜头三类素材；不能仅看生成成功或缩略图数量。对照原片记录漏掉的短流程、动画误报和配图是否代表该段，再决定是否进入自动整理。

源文件只读，输出目录不覆盖；失败时保留 `status.json` 和已生成图片便于诊断。完成页与索引只有通过源 revision 复查后才生成。源文件在读取后继续变化时，已有 HTML 属于历史快照，agent 应重新用 `visual-read` 检查，不能直接作为当前证据。
