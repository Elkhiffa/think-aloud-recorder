# 画面变化候选：本地试验版

这一步先机械检查录像，再让外部 agent 结合原话和操作理解过程。它不会调用模型、上传素材、改写场次、生成体验事件或覆盖已有分析；也没有挂到每次录制后的自动任务里。

## 使用

使用带 PyAV、NumPy 的软件运行环境。在安装包中，接口位于 `app/agent_cli.py`；从源码运行时应使用当前源码对应的环境。以下路径是示例，输出必须放在资料库之外的**新目录**。

```powershell
$python = 'D:\Think Aloud\app\runtime\python.exe'
$cli = 'D:\Think Aloud\app\agent_cli.py'
& $python $cli visual-nodes 'D:\think-aloud-database\场次\某个场次' --output 'D:\Think Aloud Development\evidence\某次检查' --max-images 120
```

默认检查整场，`--start 50 --end 85` 可先验证一段。会逐帧解码所选范围，不是每隔几秒给模型一张图。检测使用最长边 320 像素的画面；图片输出最长边 960 像素。低分辨率检测可能漏掉很小的文字或颜色态变化，需要用真实录像检验阈值，不能承诺语义完整。

结果为 `index.json`、`images/` 和 `review.html`。直接打开 HTML 可以检查候选图；若浏览器不允许它播放原视频，可运行仅在本机监听的检查页服务：

```powershell
& $python $cli visual-review 'D:\Think Aloud Development\evidence\某次检查\index.json'
```

打开返回的本机 URL；在终端按 Ctrl+C 结束。服务只提供该检查页、列入索引的图片和绑定的一个视频，支持定位播放，不提供目录浏览。URL 含随机访问路径。页面有原话和游戏截图，是私人工作材料，不能直接加入公开仓库或安装包。

## 性能与取材统计

新提取同时生成轻量 `metrics.json`，不包含原话正文或图片数据。它记录第一遍供帧、缩放、差分与检测收尾、选图、第二遍供帧、截图缩放编码、图片校验写盘、原话／输入关联、来源复查和索引／检查页发布的分段耗时，以及帧、节点、配图、未配图和省略数量。失败输出标为 `failed`，只代表部分工作。

耗时是单次任务中调用者经历的墙钟时间，包含系统调度和等待，不是 CPU 核时；并发任务的耗时不能相加当作整批墙钟时间。供帧包含视频打开、定位、解码和时间戳处理，差分项包含检测器内部预处理与状态维护，截图编码项包含缩放；尚不能据此区分原生解码器内部线程耗时。总时间止于索引与检查页保存，排除统计／状态文件写入和 CLI 回应。无法归入阶段的开销单列，阶段没有重叠计时。

`image_pass_frames` 和 `image_pass_last_frame` 反映第二遍实际供给的帧；选图取齐后就停止，不等于一定扫描到片尾。0.6.7 增加 `detect_decoder_frames`／`image_decoder_frames`，统计解码器返回的全部帧，包含定位后的前滚和边界探测，不是压缩包数量或解码器内部线程工作量。`image_decode_requests` 包含每次定点请求及可能的顺序恢复，不能只用交付图片数估算定位成本。节点数量、图片数量和“已解码全部帧”均不代表 agent 实际查看了画面或语义覆盖完整，缺图和省略范围仍须检查。

`visual-read` 额外返回 `read_metrics`：整份索引读取解析、素材有效性复查、筛选与图片路径解析的耗时，以及本次返回节点数、唯一图片路径数、`data_characters_without_read_metrics`。字符数按未包含 `read_metrics` 的 data 对象 JSON 计算，排除 CLI 包装，不是 token 数；图片路径返回也不代表图片已被模型看过。旧索引仍可读取。此轮未引入缓存，读取仍会解析整份索引并验证素材 revision。

## 检测和预算

- 使用相邻帧变化、相对参考画面的累积变化，以及网格内局部变化共同找候选。保留实际显示时间戳，不使用帧序号除以帧率推算。
- 连续动画/镜头活动合成 `motion` 区间；短变化返回旧画面保留为 `transient`，A→B→A 的再次出现不会全局去重。局部变化须满足突变、严格稳定和新近发生才升为主要候选，可以与连续运动区间重叠。更弱的变化保留在各节点的 `motion_observations` 中，默认不单独配图，需要时按时间补看；检查页有折叠列表。弱观察的独立限额也是 4000，遗漏会披露。
- 稳定段保留 `context` 作为前后文。`change` 只表示像素变化，不能直接叫“打开背包”或推断玩家目标。区域框只是机械差分区域。
- 默认最多选择 120 个配图时间，可设置 1–500；优先给变化与首尾上下文分配代表图，再给运动段和其他上下文配图，最后补前后图。同级候选超出预算时按时间均匀分配。同图文件可以复用，各次出现的时间不会丢掉。
- 配图达到预算不会删除候选。`unpictured_nodes` 表示无图候选；每个帧引用的 `path: null` 表示未配图。节点索引默认上限 4000，超出时另报 `node_index_complete: false` 和遗漏范围，需分段重跑。
- `coverage.complete` 只描述所选范围内视频画面的检查情况；它不是界面流程召回率，更不是体验目标覆盖率。请求范围、实际显示范围、首尾无画面的缺口分别保留，哪怕不到 0.1 秒也披露。还需检查 `node_index_complete`、配图缺口和原片。截取范围落在两帧之间时，保留跨越起点的前一帧，图片仍使用其原始时间戳。
- 视频须已保存，录制中的场次拒绝提取。逐字稿可暂缺。原话、说话者身份和操作同步沿用现有证据接口；原始输入偏移只应用一次。操作摘要有数量上限，完整操作仍需通过现有 `evidence` 按区间读取。
- 默认检测与截图各顺序解码一遍，限制为两个解码线程；不会启动 OBS。缩小画面发生在解码之后，长片仍有本地 CPU 和磁盘成本。此版没有硬件加速或后台自动重试。

0.6.6 在每次检测中复用同一个画面缩放器，避免逐帧重新建立转换上下文；仍逐帧解码、使用相同缩放尺寸和插值、保留实际时间戳与原检测阈值。没有减少第二遍配图解码。索引／计划格式不变，已有有效索引应继续复用，不能因为性能更新重跑已完成场次。短样本耗时只能说明该机器和素材下的结果，不能直接外推整场加速比例或模型 token。

0.6.7 可显式指定 `visual-nodes ... --image-mode seek`，仅改变配图阶段：按第一遍检测选中的原始时间戳定点解码，选图规则及完整检测保持不变。默认仍是 `sequential`。长录像配图稀疏时可试用；长 GOP、密集选图和反复打开文件可能抵消收益，没有自动按视频长度切换的规则。

容器定位可能越过某个原始帧，尤其在重排帧附近。此时只恢复一次原请求范围的顺序解码，收集尚未完成的图片；不逐点回扫、不重跑检测、不用邻帧代替。成功响应和 `metrics.json` 的 `image_sequential_recovery` 明示触发时点、返回时点及尚未产出的原帧目标数（remaining_targets，不代表编码写盘是否成功），全部定位和恢复成本计入统计。这时可能没有加速，仍需按实际耗时判断。顺序恢复后仍缺失原时间戳则失败，不发布索引。不会覆盖已有索引或重置分析预算。

## Agent 按需读取

```powershell
& $python $cli visual-overview 'D:\Think Aloud Development\evidence\某次检查\index.json'
& $python $cli visual-read 'D:\Think Aloud Development\evidence\某次检查\index.json' --offset 0 --limit 30
& $python $cli visual-read 'D:\Think Aloud Development\evidence\某次检查\index.json' --start 50 --end 85 --limit 30
```

索引可分页，每次最多 100 个候选，返回图片绝对路径、实际时间、原话引用和有限操作摘要。读取时检查素材 revision，素材/转写/同步变化后拒绝使用旧索引。revision 沿用原接口的文件大小、修改时间和相关设置指纹，不是内容签名。

先用 `visual-overview` 获得覆盖整个索引范围的紧凑导航（默认 32 个分区，`--bins` 可设 1–120）。它只返回数量表、配图与输入缺口提示、候选省略范围，不重复输出原话、按键引用和低层变化详情。这只是将已有完整节点分组显示，不重新按固定间隔抽帧，也不替代节点索引。跨分区的长节点会重复计入重叠数，起点数只计一次；关联原话数不代表整段逐字稿。旧索引也可使用，仍需来源有效性检查。

Agent 应单独完整读取原话一次，结合概览选择时间区间，用 `visual-read --start ... --end ...` 展开并实际查看图片。无原话、短暂返回、无配图或索引省略的区间仍须处理或明确标注未审查，不能因概览没有正文就跳过。此入口降低首次返回体积，不证明总模型用量降低；后续展开的次数和实际看图量需分别记录。首轮读概览不代表完成事件分析。

从 0.6.5 起，日常区间定位优先用 `visual-candidates INDEX --start 580 --end 605 --limit 24`。它先筛出区间内的主要／弱候选，再统一分页（1–60 条），只返回 ID、层级、起止时间、区间内帧时点与配图数量；不重复带出整段 motion 的弱变化、原话或按键。返回 `next_offset` 表明还有候选，不是要求读完所有页。范围最长 120 秒。`visual-read` 保留原有详细格式供明确需要完整字段的程序使用；哪怕只读一个节点，长运动节点的附属内容也可能很大，不能把 `limit=3` 当作小文本保证。

0.6.7 增加筛选：先用 `--level primary` 查看主要候选，再围绕具体疑点用 `--level weak --parent v000123` 查看该节点已保留的弱观察；省略 `--parent` 可查区间内所有已保留弱观察。默认 `--level all` 保持原分页顺序，筛选先于分页；不能在层级之间复用 offset。`matching_by_level` 披露该时间范围内保留的两类数量，主要行末的 `retained_weak_in_range` 说明可展开数量。弱观察不是无用噪声，主要候选也不等于语义重要：短暂 UI 变化可能只出现在弱观察中。

`omissions` 保留全索引的遗漏数量和时间包络，并标出是否与当前查询相交；包络内不是每一秒都存在缺失。筛选后主要列表读完仍不代表原索引完整，不改变 `node_index_complete`。这些读取不取图、不耗取材预算；实际补图继续使用原计划。

建议 agent 先读小批节点索引，根据前后连续性选择图片，遇到遗漏、长 motion 区间或证据矛盾时再回看该范围。不要一次把全部图片都传给模型。机械索引的图片上限不是模型必须阅读的数量；支持下面的取材计划时，实际图片通过同一个计划发放，不能另建目录绕过其预算。

体验目标与问题的输出格式仍保持 v1。Agent 应先结合整场节点与全部原话，还原主要目标、尝试、转折和结果，允许“目标未明”；然后从事件中分析阻碍和问题。正常过程与无原话区间也属于覆盖范围。区分画面观察、原话明确表达和目标推测，机械节点的数量不等于体验事件的数量。

重做既有分析时，先备份上一轮评估报告，再通过 `reprocess --worker ... --reason ...` 领取：接口备份并校验旧结果，保留旧结果可读，直到新结果提交成功。只换方法不改素材 revision；对比应绑定相同场次与素材版本。具体方法见源码 `skills/think-aloud-preprocess` 与 [外部接口](agent-integration.md)。

## 共用预算的取材计划

`visual-plan` 复用已完成的索引，保留原始候选和图片，只在资料库外建立分组、首轮选图和发放账本。它不运行模型、不领取分析任务、不修改已有事件。以下命令需要包含此功能的源码／安装版本，先用 `--help` 确认支持；旧的 0.6.3 安装不自动获得新接口。

```powershell
& $python $cli visual-plan "$work\visual-pass-01\index.json" --output "$work\evidence-plan-01" --total-views 24 --initial-views 12 --review-views 4
& $python $cli visual-packet "$work\evidence-plan-01\plan.json" --request-id first --phase initial --question '浏览整场主要过程的候选画面'
& $python $cli visual-packet "$work\evidence-plan-01\plan.json" --request-id popup --phase inspect --question '短弹窗出现后是否返回原界面' --start 679 --end 681 --limit 6
& $python $cli visual-packet "$work\evidence-plan-01\plan.json" --request-id check-balance --phase review --question '复核余额变化前后状态' --at 785 --at 875
& $python $cli visual-budget "$work\evidence-plan-01\plan.json"
```

- 默认总额 **24**、首轮上限 **12**、复核预留 **4**，是小样本试验起点，不是已证明足够的整场分析配置。参数可在开始前设置；之后所有分析者、补图、复核共用该计划。计数单位是**发放的原始时间点次数**，同一图再次用于复核也占一次；拼成一张联系表不会变成只算一张。未实际查看的已发图仍保守计入。默认首轮发满 12 后，普通补图最多还可用 8，复核至少保留 4。
- 相邻候选图经本地低分辨率像素相似度或同一机械 `motion` 区间分组；遇主要变化节点分开。不会跨时段全局合并 A→B→A。**近似像素不是相同界面状态**，小文字、数字或选中态可能被忽略；精确比较须按具体时间补图。保守规则可能完全不压缩旧候选，不能预设分组必然省图。
- 0.6.5 的首轮每个连续组只取代表时点，按时间空档分散，避免一串近邻动画占用多个名额；不再强制将短变化的前／中／后图一起塞进首轮。近乎全黑的候选在有其他可用图时暂缓；这不证明黑屏无语义。原始三图组仍保留，未完整发放的组列入 `deferred_transitions`，必要时定向核对。数量是上限，候选不足或过于集中可以少发；同一计划只发一次首轮。它不是按固定频率重抽帧，也不证明已经覆盖全部目标。
- 补图／复核必须注明要核对的问题，指定 1–12 个时间点，或至多 120 秒的区间及 2–12 张上限。0.6.5 的区间取材保留两端，比较主要及弱变化的持续时间、相邻帧变化与运动比例，优先较稳定区间的中段，并压低贴近已选时点的近邻。`transient` 使用原峰值帧；强烈的末端动画不再因候选类型直接占优。`deferred_bundles` 披露未完整发放原始各帧的组；发出一个中段不等于整组已检查。问题文字用于留痕，程序不理解其语义。已有图片直接复用，缺图只在所需时间附近定位解码，保留实际显示时间戳，不重新解码整场。
- `budget_exceeded` 不取图也不增加计数。预算不足时保留具体未查范围与待核对问题，不自动扩额、另建计划、遍历全部索引图或让其他 agent 重看整场。`pending`／`failed` 保留名额，不自动重试。重复同一请求编号只取回原回执，不再计数；实际再看一次须用新编号。短暂跨进程锁防止多个调用分别花完同一额度。
- 回执中的 `frames` 是图片路径、时间和 SHA-256，不是已看图证明。源 revision、索引摘要或缓存图片不匹配时拒绝复用。源码索引、原片和旧分析保持原位。计划、账本及图片缓存是私人取材材料，不能加入公开包。

这是**取材入口的发放额度**，不是模型计费限制：直接调用旧 `frame`、直接打开图片、重新读取长文本或另建计划不受程序拦截，执行者必须遵守同场预算。仍分别记录文本读取量、已发图数、实际看图次数及复核次数；没有真实用量数据就不能给出 token 节省比例。小包功能验证后，需要另行获准的单场试验才能判断模型整理质量和实际耗用，不能直接恢复整库任务。

新计划使用 `version=2, selection_version=2`，需要 0.6.5；0.6.4 会拒绝其计划版本。0.6.5 可继续读取旧索引和旧计划：未带 `selection_version` 的旧计划沿用原区间排序，已发图、回执和已用预算不变。不会自动升级旧计划或重置账本。下一未开始场次可建立新计划；已用完的场次若需工程回归，另存明确标注用途的工程记录，不得伪装成新的分析额度。

这个修正仍是数值排序，不是弹窗识别。长运动中的“较稳定”候选可能是边缘 HUD 或战斗间歇；候选差分区域不等于图中可见弹窗的位置。S11 已知 580–605 秒回归能在 4 张内取到完成弹窗和前后画面，但首轮主要过程的语义覆盖、其他游戏和未知短状态仍待逐场检验。保守相似分组不保证压缩候选数。

区间自动排序仍可能因时间距离抑制排除独立短状态。需要核对具体过程时，可先在短窗口读紧凑候选，再以原计划 `--at` 显式取材：状态内容可取 `context` 内部点；切换、返回或重置问题还需检查相邻状态之间的 `change`／`transient` 代表点及必要前后证据。两侧稳定段相似不证明中间没有复位，也不要求把所有中点或峰值都看完。`context` 只是低变化区间，演示动画可能将同一界面分成多段，不能一段当一个 UI 状态。已有图能回答问题时停止补图；候选多于剩余额度时缩小问题并标明未查范围。

原话可能在回顾刚才的操作。结合原话前文、可见界面对象和已有输入定位所述动作，不把说话时间直接当成动作时间，不使用固定前移秒数或改同步偏移解释回顾性描述。上述选点是分析者判断，需记录索引路径／SHA、候选 ID／区间、裁剪和选择理由，再关联请求 ID、实际 PTS 与图片 SHA；`--at` 回执的空 `selection` 不代表自动排序或语义选择已发生。

## 检验方法

至少比较局部 UI 连续操作、短弹窗返回、动态游戏镜头三类素材；不能仅看生成成功或缩略图数量。对照原片记录漏掉的短流程、动画误报和配图是否代表该段，再决定是否进入自动整理。

源文件只读，输出目录不覆盖；失败时保留 `status.json` 和已生成图片便于诊断。完成页与索引只有通过源 revision 复查后才生成。源文件在读取后继续变化时，已有 HTML 属于历史快照，agent 应重新用 `visual-read` 检查，不能直接作为当前证据。
