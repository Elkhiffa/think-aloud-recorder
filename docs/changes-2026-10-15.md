# Think Aloud 0.8.1

洞察窗口改为“洞察 → 议题 → 子议题”三层，并新增“界面库”：可以按系统、玩法标签和判断类型筛选证据。agent 整理的议题和界面名默认接受，用户通过反馈纠错。软件更新可以只下载改动的文件。

## 洞察窗口

- 证据树分三层：洞察 → 议题 → 子议题，中间的议题层按需设置。收起后的树就是目录，不再单独显示目录。洞察和议题两级按证据条数从多到少排列，BUG 放在最后。
- 滚动时，当前所在的洞察、议题、子议题固定在顶部；同一洞察的下一个议题和下一个洞察停在底部，点击即可跳过去。
- 可展开的条目带浅色底，层级越深底色越浅。议题编号改成小号字，放在条数后面。
- 说明文字里的实例号（如 `0921·1406 i085`）和议题号显示为小号引用，点击后定位到对应证据。
- “全部展开 / 全部收起”旁固定显示全部判断类型和条数，可以多选筛选，也能一键清除。每一层下面还显示该层的类型分布，点击同样会筛选。
- 左栏可在“报告”和“界面库”之间切换：
  - 界面库是多维度标签，维度包括跨系统、系统、活动 / 玩法，由资料库里的 `tags.json` 提供。维度是可收起的大标题，标签是网格卡片，封面图在上，名称和条数在下。
  - 点标签卡片会筛选右侧证据，可以多选。标签筛选可以和类型筛选叠加。
  - 在证据卡上右键，选“设为封面”，即可更换对应标签的封面。
- 筛选更新后，展开 / 收起状态、滚动位置和最后点击的位置都会保留。
- 去掉“议题确认”“界面确认”两个页签。agent 整理的议题和界面名默认接受。每个议题、证据卡和标签旁边有铅笔按钮，可以写一句“哪里不对、该怎么调”，内容存进资料库的 `feedback.json`，「反馈」页签列出全部反馈及其处理状态。

## 资料库与外部 agent

- 议题表最多三层。`issues-move` 可以把议题挪到别的上级，编号、对应和场次结果都不变。一条证据可以同时挂到多个议题下。
- 新增 `tags-report`、`tags-write`：标签由活动、关键词（只匹配证据所在界面的正式编号）和逐条增减三部分合成。新增 `feedback-list`、`feedback-resolve`。
- 界面命名改用“界面组”规则：编号写成 `入口名/一级页签/二级页签`，入口名和标题不一致时写成 `入口名（标题）`。新增 `catalog-rename`，旧编号会保留为别名；提交结果时，引用别名的界面也会通过校验。
- 判断类型新增“操作成本”。BUG 关键词增加偶现、不显示、超框、看不全、悬空、标错。活动标题要写明是从哪个系统或玩法进入的。

## 更新与词库

- Release 新增 `-app-update.zip`：从 0.8.1 起，软件内更新只下载改动过的文件，其余文件由已安装的版本补齐并逐个校验；校验不一致时自动改为下载完整包。0.8.0 的更新器还不支持这个包，所以从 0.8.0 升到 0.8.1 时仍会下载完整包。
- 转写词库：UI/UX 词表扩充到 536 条，燕云词表扩充到 1166 条，补充的是 21 场整理中核对出的误听原词，以及新出现的玩法名、系统名。
