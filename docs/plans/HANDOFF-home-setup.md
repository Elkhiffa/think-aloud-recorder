# 交接：在家里这台电脑上用上 0.10.0（2026-10-24）

给家里电脑上的 agent。0.10.0 起，安装版自己就能跑完整个分析流程：文字识别组件在软件里下载，两份分析 skill 随软件包、点一下就装，界面路径识别在设置里启用。家里**不需要源码目录或开发 runtime**。按顺序做，每一步完成后向用户汇报“做了什么、怎么核对的、结果是什么”。遇到和这里描述不符的情况，先停下问用户，不要自行变通。

## 规矩

- **真实资料库**：只有第 4、5 步会写，写的是界面目录里的 `layout` 和各场的 `context-track.json`。其他文件只读。
- 软件里的按钮让用户自己点，不要替用户点安装或下载，也不要直接改安装目录。
- 不全局安装任何东西，不读 `analysis` 目录，不输出密钥或完整配置。
- 家里的路径和公司不同，以实际为准。不知道就问用户。

## 0. 先弄清两个路径，告诉用户并请他确认

1. Think Aloud 安装目录：有 `Think Aloud.exe` 的文件夹。下面说的“软件目录”是它里面的 `app` 文件夹（有 `agent_cli.py` 和 `runtime\python.exe`）。
2. 资料库里燕云的文件夹：形如 `<资料库>\燕云十六声`，下面有 `场次\` 和 `game-assets\燕云十六声\catalog.json`。

下面的命令都在软件目录里用 PowerShell 运行，`PY` 指 `.\runtime\python.exe`。

## 1. 把软件更新到 0.10.0

- 让用户在 Think Aloud 里点：设置 → 通用 →「版本与更新」→ 检查更新 → 下载 → 退出并更新。0.8.1 和 0.9.0 都只下载改动的文件（增量包）。
- **核对**：软件目录里 `portable.json` 的 `version` 是 `0.10.0`。

## 2. 下载识别组件（文字识别）

- 让用户点：设置 → 通用 →「识别组件」→ 下载 → 开始下载。约 65 MB，来自 files.pythonhosted.org，下载后逐个核对校验值再解压；可以暂停、继续，更新软件时保留。
- **核对**：`.\runtime\python.exe -B -X utf8 agent_cli.py ocr-status` 返回 `"ready": true`。

## 3. 安装两份分析 skill

- 让用户点：设置 → 通用 → 记录方法 →「安装分析 skill」。只装进这台电脑已有的 Claude Code / Codex 技能目录；旧副本内容不同时先备份到软件目录的 `state\skill-backups\` 再写入，用户自己加的文件保留。
- 结果对话框列出每处装了什么、备份在哪。把它告诉用户。
- 如果技能目录里还有旧的 `think-aloud-preprocess`，问用户要不要移走。它已经停用。

## 4. 给资料库启用界面路径识别

- 让用户点：设置 → 游戏 → 选燕云 →「界面路径识别」→ 启用。旧目录以 `catalog.json.before-layout-<时间>` 留在旁边。
- 如果已经写着“已启用”、没有启用按钮，说明加过了，跳过这一步。
- **核对**：`.\runtime\python.exe -B -X utf8 agent_cli.py catalog-validate "<资料库>\燕云十六声" "燕云十六声"` 返回 `"ok": true`。

## 5. 重建已有场次的情景轨道（耗时，建议夜里跑）

设置里那一行给出了可复制的命令，等同于：

```powershell
.\runtime\python.exe -B -X utf8 agent_cli.py context-rebuild "<资料库>\燕云十六声" --game "燕云十六声"
```

- 两场并行。旧轨道没有字框角点，会整段重跑文字识别：一小时录像约 20–60 分钟，CPU 占用高。
- 中断了照原命令重跑即可，已经按当前规则建好的场次会跳过。每场一个日志，在软件目录的 `state\logs\context-rebuild\`。
- **核对**：最后的 JSON 里 `failed` 是空的。不空就看对应日志，把错误原样告诉用户，不要改代码绕过。
- 新录的场次不用单独处理：之后整理时建情景轨道，会自动带上页签和标题信息。

## 6. 转写修正：知道就好，这一步不用做

- 公司那台电脑的资料库根目录有 `transcript-corrections.json`：确认过的转写修正，包括“走交 / 左交 / 左焦 → 走焦”等全库规则和逐句修正。
- 家里的资料库如果是另一份，就没有这个文件。不要从别处复制过来，那些修正绑定的是公司库里的场次。
- 以后在家整理场次时，按 skill 里“转写修正”一节，用 `transcript-fix-propose` 提议，交用户确认。

## 汇报

全部做完后，交给用户一张表，每一步一行：做了什么、核对命令和结果、有没有异常。
