## 1. 已确定的决定（由用户拍板，不要重新讨论）

- **手段服务分析。** OCR、小模型、外部识图、内部跑测时读客户端，都只是丰富记录的方式；一律以“是否让体验设计分析更完善”来评估，并用真实场次材料判断（已写入 AGENTS.md）。
- **路线 A：先跑通价值链，再由缺口决定开发。** 已在三场真实场次上跑通（见第 2 节），用户认为产出“对体验设计分析非常有价值”，作为后续的**效果示例**和质量基准。
- **界面识别只覆盖全屏界面和侧窗。** 全屏界面识别到“顶部一级页签 / 左侧纵向图文页签 / 横向文本页签”的选中项；侧窗只需标题；背包是特殊侧窗，左侧可展开抽屉弹窗。HUD 和场景不需要自动识别，记录者会口述。
- **整理工作分情景。** 单场次和多场次的初次整理不打议题标签（记录者明说“以前也遇到过”时写进陈述）；只在跨场次分析时挂标签。标签存储先试“输出一张表”（已试，有效），下一批升级为资料库级的“议题 → 实例”对应表。
- **实例粒度要细。** 一条实例对应一句话里的一个点，便于 agent 分析和追溯；给人看的界面再按活动或连续判断折叠展示。
- **记什么。** 判断（困惑、阻碍、正面、期待、建议、自我纠正）加上带设计信息的观察（理解时刻、使用习惯与取舍、注意到某个设计）。流程叙述、照念数值或文案、对 NPC 的回应不记，留在逐字稿里可检索即可。
- **议题。** C-2“界面里的名词或图标能否就地弄懂”单独成题；C-1“红点和新标记何时算看过”并入 TA-04：红点和播报都是引导注意力的提示，失效的本质是注意力引导没达到设计预期。TA-04 的标题是否随之调整，由用户在下一批确认。

## 3. 缺口清单（按 4 个 agent 中独立提出的次数排序）

1. **界面名跨场次不统一（4/4）**：各场自定名字，9-28 有 29% 为空；为确定当前界面和选中页签截了大量画面。
2. **回顾识别偏弱，格式表达不了“指向本场之前”和“比较两个时刻”**：约 11–12 处真实回顾只标对 6 处。
3. **判断类型缺“负面评价 / 价值判断”（2/4）**。
4. **实例不能引用操作记录，操作记录没有可读摘要（2/4）**。
5. **议题标签只能存在表里**：`instances-query --issue` 查不到；查询不带出所属活动和证据；活动缺“玩家当时想做什么”。
6. **写法规则覆盖不全（3/4）**：无标题菜单、结算整屏、弹窗、游戏外窗口、跨界面的泛泛评价；陈述里原话和转述混在一起。
7. **领取令牌只返回一次**：丢失后只能等租约到期。skill 要求所有文件放在工作目录、领取后立即续期确认。
8. **重做会覆盖旧结果的 ideas / questions**：有 agent-history 备份，在真实资料库重做前要定保留方式。
