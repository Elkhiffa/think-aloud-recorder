# 改版决定（2026-10-19）

本文件记录 2026-10-19 与用户逐项确认的改版决定，是本轮前端改版的依据。改版在分支 `feat/frontend-redesign` 上进行；性能修复另开任务，不在本轮。

## 产品骨架

- 主窗口是纯录音机。它常年开在副屏的小窗里，按 720 宽设计，更宽时只加留白。
- 场次库和洞察合并成“资料台”大窗口，用标题栏页签切换“场次 / 洞察”。资料台全局只开一个，跟随主窗口的当前项目。
- 三个窗口（主窗口、资料台、回看）都去掉系统标题栏，改用自绘标题栏。标题栏只当窗口外框用：左侧放小标，中间是可拖动的空白，右侧是三个窗口按钮，不放页签和功能。自绘标题栏要补齐：拖动、双击最大化、拖到屏幕边缘贴边、四边四角改大小、窗口阴影。Windows 11 鼠标停在最大化按钮上弹出的分屏布局，这一项不提供。

## 主窗口

- **页面标题**：页面的第一个区块就是标题。当前游戏名用大字，其他游戏跟在旁边用小字，点一下就切换；放不下时收进“更多”。不区分主游戏和竞品。
- **空闲时**，只显示这几样：
  - 录制键；
  - 上一场：标题、日期和时长、问题数、一句原话；
  - “全部场次 →”和“洞察 →”两行。

  录制方案不露出，项目名不重复出现。
- **异常时**：隐藏所有就绪小圆点，出问题的那一项改成醒目提示，写清原因，并附“去设置”或“重新检查”。
- **录制中**：整页只剩计时、麦克风音量、键鼠和手柄记录状态（含游戏是否在前台）、结束按钮。
- **刚结束**：上一场的位置依次显示保存中、转写中、待整理、已整理 N 个问题。
  - 待整理时附“复制整理指令”：把场次路径和整理提示复制到剪贴板，内容跟随单场整理的交接文档。工具不内置 agent，也不上传任何东西。
  - 失败时，也在这个位置醒目地显示。
- **原话的挑选规则**：优先“阻碍 > 操作成本 > 困惑 > 负面”，只取置信度高的，长度 8–24 字，不以语气词开头，原样引用，不做任何改写。
- **新项目还没有场次时**：正文写“还没有记录。点开始录制，边玩边说出你此刻的想法。”；“全部场次”和“洞察”两行先不显示。

## 资料台

- 标题栏左侧是项目名，接着是“场次 / 洞察”两个页签，右侧是窗口按钮。
- **场次视图**：
  - 左边是按月分组的列表，月份标题吸顶。每行有页边日期、标题（未命名的显示“未命名”加前两个活动标题）、时长、状态、问题数和一条细色条。
  - 右边是选中这一场的详情：和回看相同的「问题 / 体验事件」两个视图（问题分布由页签和类型筛选给出），以及全部操作——回看、整理或重试、复制整理指令、重命名、导出、资料文件夹、原始录像、恢复云端任务。
  - 列表顶部用标签多选筛选：状态（全部 / 待整理 / 已整理 / 失败）和问题类型。排序可选时间或问题数。文字搜索收成一个图标。
- **洞察视图**：保持现有结构，只换视觉。
- **互相跳转**：
  - 场次详情里列出“这一场的证据挂在哪几个洞察下”，点击后切到洞察视图，只看这一场的证据；
  - 洞察里证据卡上的场次名可以点，点击后切到场次视图并选中那一场。

## 设置

- 在主窗口里以覆盖层打开，是一页表单，底部固定“保存 / 取消”。齿轮打开时，默认停在“游戏设置”。
- **游戏设置**（每个游戏各一份）：
  - 显示名称（改名不移动文件夹）；
  - 游戏窗口；
  - 游戏专有词库；
  - 保存位置（只读，可以打开文件夹）。
- **通用设置**：
  - 麦克风；
  - 录制范围、画面质量；
  - 是否记录键鼠与手柄；
  - 转写方式、密钥、转写语言；
  - UI/UX 通用词库；
  - 资料总库位置；
  - 记录方法说明；
  - 版本与更新渠道。
- **向导**只在第一次使用和新建项目时出现。新建项目分三步：
  1. 游戏名、游戏窗口；
  2. 麦克风与转写，第一次使用时才有这一步；
  3. 保存位置，默认是“总库\游戏名”，可以另选。

  “记录方法”说明只在第一次使用时出现。
- 现有设置规则全部保留，包括：
  - 预设保存成功后才保存密钥；
  - 词库并发检查；
  - 资料库复用确认；
  - 部分失败按编辑重试；
  - 录制中锁定设置；
  - 重新连接录制引擎的入口。

## 视觉

- **方向**：田野笔记。红色页边线、页边日期数字、原话引文、目录导引线。录制键是红色胶囊，也是全页唯一的实心色块。
- **字体**：宋体（思源宋体）只用于大标题、日期数字和原话。没有思源宋体的系统退回黑体粗体，不退回系统宋体。其余文字一律用等线或微软雅黑；数字用 Georgia；时间码用 Consolas。
- **尺度**：
  - 间距只用 4 / 8 / 12 / 16 / 24 / 32 / 48；
  - 圆角统一为 4px：按钮、输入框、标签、提示块、录制键一律相同；只有小于 12px 的状态点不受限制；
  - 字号只用六档：12 / 14 / 16 / 20 / 28 / 48。
- **问题类型配色**：困惑是赭黄，阻碍是朱红，操作成本是靛蓝，负面是紫，其余类型都是浅灰。三个窗口统一使用这一套；颜色只用在“问题”上。
- **深浅色**：暂只做浅色，见第四轮。
- **动效**：只在空闲切到录制中、录制中切到保存、异常提示出现这三处使用。系统开启“减少动画”时全部关闭。

## 数据与迁移

- **项目**：一款游戏就是一个项目，各自一个资料库文件夹。软件里不登记主游戏和竞品的关系：如果只是预研某个品类，可能根本没有主游戏。
- **资料总库**：下面按游戏分文件夹。现有资料库根目录的内容搬进 `燕云十六声\`，只有 `.obsidian`（Obsidian 对整个库的配置）、`分析`、`.experience` 三样留在总库根目录（2026-10-20 用户确认）。跨游戏分析放在总库根目录的 `跨游戏分析\` 下。这一轮只建好约定，不做界面。
- **搬迁方式**：由用户在没人使用资料库时亲手运行脚本：
  1. 先预览要做什么；
  2. 在同一磁盘内移动，硬链接不受影响；
  3. 搬完自动核对：45 场都在、对应 0 失效、报告引用 0 未解析；
  4. 同步改写安装版配置里的路径，改之前先备份。

  搬迁放在开发版验证过新结构之后进行，搬之前通知内容分析会话和 Codex 暂停。
- **不改名的东西**：项目改名不移动文件夹；场次文件夹名不改，新场次也沿用现在的命名规则。
- **新项目位置**：默认放在总库下，也可以另选位置；各窗口一律按项目记下的路径查找。
- **现有预设的迁移**：
  - 通用设置取自当前正在用的预设；
  - 每个资料库对应一个游戏，它的游戏窗口和游戏词库取自对应的预设；
  - 同一资料库下有多套预设时，以当前那套为准，其余的备份；
  - 原配置先备份到 `state/`。

## 记进 roadmap

- 用语音做标记：整理时从逐字稿识别“这里记一下”这类说法，录制中不用多按任何东西。
- 支持更多转写 API 渠道。
- 跨游戏分析的界面，按 `跨游戏分析\` 下的路径呈现。

## 第二轮追问的修订（2026-10-19）

- 去掉“第 N 场”：用户在两台机器上交替录制，本地无法知道下一场的编号。
- 不再区分主游戏和竞品，页签只是不同的游戏。
- 日期挂在场次标题的左侧，两者之间不加分隔线。
- 页边线和窄栏是否保留、选哪个视觉方向，由新一轮主界面探索决定，样稿见 `work/redesign/explore/`。

## 第三轮：视觉定稿（2026-10-19）

视觉稿见 `work/redesign/b/`。

**方向**：选定 B（笔记 · 窄栏）。

**主窗口的构成**：
- 左侧 56px 窄栏，右边缘是一条红色页边线。窄栏顶部放 28px 的标记，左下角只放“记录方法”和“设置”两个图标。
- 窗口顶部就是页面标题：当前游戏名用 48 宋体，其他游戏用 20 宋体，后面跟一个“＋”图标。页签顺序固定，不因切换而重排。
- 放不下时，当前游戏名保持完整，其他游戏从后往前收进“更多”，仍放不下时“＋”也收进去（显示为“＋ 新游戏”）；只有当前游戏名单独都放不下时才截断。
- 内容只有一条左边缘，用两条分割线切成三段：
  - 第一段：录制键加“已就绪”；
  - 第二段：“上一场”标题和上一场的内容，下面是“全部场次 ······ N 场 →”。两者是同级标题，表示上一场是全部场次中的一场；
  - 第三段：“洞察 ······ N 个 →”，下面写最新报告的日期。
- 日期挂在场次标题左侧，两者之间没有分隔线。

**异常时**：提示块放在灰掉的录制键右侧，与它并排；第一段的高度不变，上一场的原话暂时收起。提示块与录制键同高（56px），不滚动：只显示第一条原因、最多两行；有多条原因或一条写不下时，旁边出现“全部 N 项 / 查看全文”，点开列出全部原因（2026-10-20 用户确认：报错信息不应该滚动）。

**录制中**：
- 第一段：计时和结束按钮；
- 第二段：收音与操作；
- 第三段：一句提示语。

页签只保留当前游戏，并注明录制中不能切换。

**窗口尺寸**：初始尺寸改为 720×600，与最小尺寸相同。原来的初始尺寸是 920×1040。

**设置**：
- 设置是软件层级的入口，因为它在窄栏里，和具体游戏隔开。
- 一级页签是“游戏 | 通用”。“游戏”下面的二级页签是各个游戏，加一个“＋ 新游戏”。打开设置时，默认停在当前游戏。
- 版本与更新整体收进“通用”。软件启动时检查一次版本（只读取 GitHub 上的版本信息）；有新版本时，在齿轮、“通用”页签和“版本与更新”这一行上都挂红点。
- 没有修改时，底栏只显示“关闭”；有未保存的修改时，显示提示文字和“取消 / 保存”。

**新建游戏**：分两步，“游戏与窗口”和“保存位置”。麦克风和转写只在首次使用时进入向导。

**线与块面**（2026-10-20 用户选 B）：块面只给可交互的东西（按钮、输入框、筛选标签、提示块、可点的列表和卡片、对话框）。线分三类处理：
- 大段落分界（主窗口三段之间、资料台和洞察的标题栏下、设置的“游戏 | 通用”页签下）只留一条很淡的发丝线，不再用墨色；
- 逐行的线（设置字段、场次列表、原话和活动列表、逐字稿行、反馈条目、对话框页眉页脚）全部去掉，靠间距分组；面板之间的分隔线改成一侧有底色（资料台左侧列表、洞察右侧证据栏）；可交互的卡片和面板只留底色、不加边框；
- 标识和交互提示的线保留：红色页边线、目录导引点、原话左侧红线、链接下划线、输入框和标签的描边、提示块的强调色条；回看时间轴、刻度、进度步骤这类图示里的线属于数据，不在此列。

**字体角色**（2026-10-20 用户要求：一屏不超过 5 种字体+字号+字重的组合）：全软件只有 7 种角色，每个画面最多用 5 种；数字不再单独用 Georgia，时间码不再用 Consolas，统一用等宽数字。

| 角色 | 字体 · 字号 · 字重 | 用在 |
|---|---|---|
| 大标题 | 宋体 48 粗 | 页面标题（游戏名、设置、新建游戏）、日期大数字、录制计时 |
| 标题 | 宋体 20 粗 | 段落标题、页签、场次名、关键数字、录制键、报告的一二级标题 |
| 阅读 | 黑体 16 | 洞察报告正文、议题说明、逐字稿 |
| 阅读加粗 | 黑体 16 粗 | 报告里的加粗句、议题卡片标题 |
| 正文 | 黑体 14 | 界面文字、标签、输入框、原话 |
| 强调 | 黑体 14 粗 | 按钮、列表里的场次名、选中的子页签 |
| 注释 | 黑体 12 | 提示、时间、引用编号、计数 |

各画面的五种：主窗口、设置、资料台·场次 = 大标题、标题、正文、强调、注释；资料台·洞察 = 大标题、标题、阅读、阅读加粗、注释；回看 = 标题、阅读、正文、强调、注释。
例外：回看里键盘键帽、手柄图示、时间轴刻度、播放头时间、空档标签是图示的一部分，字号按格子定（8–18），只统一字体。统计脚本 `work/redesign/type-audit/audit.cjs` 把它们单独列为“图示”。

**删除游戏**（2026-10-20 用户要求）：设置 → 游戏最下方的「删除这个游戏」，只在设置页出现，向导里没有。确认框默认只删设置和入口；“同时把资料文件夹移到回收站”默认不勾，勾选后要输入游戏名才能确认，资料只进回收站、不永久删除。按钮在请求进行中锁定，后端对已删除的游戏再次请求会拒绝。有后台转写时不能删；资料文件夹与其他游戏共用、包含资料总库或软件本身时只能删设置。

**设备选择的归属**：录制范围和显示器属于通用设置，所有游戏共用；游戏页只有游戏窗口，录制整个显示器时改为一行说明。“刷新设备”放在设置页顶部，游戏页和通用页（向导的“设备与转写”）都能看到；读取结果只在需要处理时显示（没找到、要选择、读取失败）。首次设置的“设备与转写”一步同时显示通用词库，内置的 UI/UX 词库在这里，不算某个游戏的词库。

**资料台**：
- 标题是游戏名（28 宋体），后面是同级的“场次 / 洞察”两个页签。
- 窄栏只放标记。

## 第四轮：合成方向（2026-10-21）

第三轮实现后，用户判断视觉层级不如安装版。随后做了一次盲评（`work/redesign/eval-packet/report.md`）和三套盲探索（`work/redesign/explore-blind/`：案卷、音轨、色谱），用户按下面的组合定稿，合成稿见 `work/redesign/composite/`。本节与前几轮冲突时以本节为准。

**组合**：
- 信息层级全软件取“色谱”：每个画面先看到什么、再看到什么，按色谱方案排。
- 配色取“案卷”，纸色更浅、略带暖色相，不用纯黑白灰。
- 场次库用“音轨”的表格排版，但去掉“时间轴上挂标记”那一列：以现在的反馈密度，在场次库的宽度下只是一团色块，看不出问题分布。
- 回看时间轴里各种标记的对比和配色沿用安装版。
- 标题用思源宋体粗体，字号取色谱方案。

**主窗口**（初始尺寸 720×520，与最小尺寸相同；更宽、更高时只加留白）：
- 左侧是 240px 宽、占满全高的录制块，整块都是录制键。右侧一栏从上到下：游戏页签 → 异常时的原因 → 上一场 → “全部场次 / 洞察”两张卡 → 底部“记录方法 / 设置”。
- 游戏页签是文字页签（2026-10-21 用户选 B）：当前游戏墨色加粗、下面一条墨色下划线，其他游戏灰字，整行下面一条很淡的发丝线；不用底色，免得和按钮混淆。设置页里的游戏页签用同一种样式。放不下时其他游戏从后往前收进“更多”，规则同第三轮。
- **空闲**：录制块写“开始录制”（游戏名只在上方的游戏页签里）；底部写“已就绪”，下面每项一行：录制目标（游戏窗口或显示器的名字）、麦克风（开启时加“操作记录”）。每行放不下时用省略号，不换行，录制键的大小不因此变化。
- **区块标题**（2026-10-21 用户要求）：“上一场”“全部场次”“洞察”是功能标题，用宋体 22，是各自区块里最醒目的字；两张卡里的数字退到标题下面一行（“45 场”“17 个 · 最新报告 10月19日”；最近一场的日期由“上一场”给出），不再用大数字。场次名前不加“未命名”。
- **上一场**：标题“上一场”和“回看”一行，下面是场次名，再下面一行“9月23日 周三 20:05 · 01:02:05”，再下面是四类问题的比例条和各类计数，最后一句原话。还没整理完时，比例条和原话的位置换成“已保存 / 转写中 / 待整理”三步进度，以及“复制整理指令”或“开始转写”。
- **「N 个问题」**只计困惑、阻碍、操作成本、负面评价四类；比例条和计数也只画这四类。
- **异常**：录制块变灰，写“暂不能录制”，底部写“N 项检查未通过 / 处理右侧事项后重新检查”。原因列在右栏顶部，最多两条、每条最多两行，不滚动；超过两条或有一条写不下时，出现“全部 N 项 / 查看全文”，点开列出全部原因（取代第三轮“只显示第一条”）。两张卡和上一场的原话暂时收起。录制块和录制键的位置、大小不变。
- **录制中**：录制块里从上到下是计时、麦克风音量、底部白色的“结束录制”条；右栏只剩提示语“边玩边说出你此刻的想法”和录制配置摘要；游戏页签只留当前游戏，注明录制中不能切换。
- **空库**：上一场的位置写“还没有记录……”，两张卡不显示。

**资料台 · 场次库**：
- 标题栏 40px：小标、软件名、当前游戏名（只显示，不能在这里切换：资料台跟随主窗口的当前游戏），再是“场次库 / 洞察”两个下划线页签，样式同主窗口的游戏页签。
- 窗口纸色上放两块纸面：左边是场次表格，右边是选中这一场的详情；不用分割线。
- 表格顶部一行：搜索框（常驻）、状态分段“全部 / 已整理 / 待整理 / 转写中 / 失败”（带数量；有后台转写任务的场次算“转写中”）、“问题类型”菜单（四类多选）、排序“最新在前 / 问题最多”。
- 表格列：日期 · 场次 · 开始 · 时长 · 问题（数字加四类比例条，只在已整理时显示）· 状态（已整理时留空）。按时间排序时按月分组，月份吸顶；按问题数排序时不分组。窗口窄时先收起“开始”一列。未命名的场次用活动名或开始时间，灰色常规字。
- 详情：元信息“9月22日 周二 · 10:30–11:32 · 1:02:05 · 2 个体验事件” → 宋体标题 → 操作 → 四类比例条和计数 → 按类型的原话 → 关联洞察 → 体验事件。
- 标题前不加“未命名”。标题后跟一个扁平的小铅笔，点一下标题原地变成输入框：回车或点别处保存，Esc 放弃，留空恢复默认名称（2026-10-21 用户要求：agent 整理后会自动命名，多数时候不需要重命名，不必占一个按钮）。
- 操作一行只放：回看、复制整理指令（未整理时）、复制资料库路径（复制这一场的文件夹路径，同回看页）、更多。“更多”里是打开资料文件夹、重新整理（预期不明确，几乎不用）、导出、原始录像、恢复云端任务。
- 每种问题类型的标题行：左侧一条该类型的强色竖条，加同色相的浅底，类型名用该类型的颜色，后面是条数，最右是 ▼（展开后转向）；原话放在标题行下面的纸面上。先显示 3 条；超过 3 条时点标题行展开全部，再点收起。
- 能跳转的行（原话、体验事件、关联洞察）悬停或键盘聚焦时，最右边出现一个朝右的小箭头。原话和体验事件点一下在回看里打开那一刻（体验事件从开始时间打开），关联洞察切到洞察页。

**资料台 · 洞察**：结构不变（左栏报告或界面库，右栏证据或反馈），只换配色和层级。报告和界面库直接放在窗口纸色上读，大标题宋体 22，小节标题黑体 14 粗，正文黑体 14；右栏连同栏头是一块纸面。每栏有自己的栏头：左栏是“报告 | 界面库”、报告选择、刷新和状态；右栏是“证据 | 反馈”（与右栏左对齐）和“全部展开 / 全部收起”（与右栏右对齐，只在证据页出现，用安静的文字按钮，和筛选区分开）。两组页签是分段控件；问题类型筛选也放在底色组里，选中时是墨色，和界面来源筛选一致。议题行、界面分类、证据卡只用底色、不加描边，层级越深底色越浅；议题行圆角 8，子议题 6。引用是小号底色标签；资料库里找不到的引用用警示色并在后面写“· 找不到”，不再用删除线。原来用红色的强调（悬停、选中）一律改用墨色。

**回看**：结构不变，只换配色和层级。标题区左上是和其他窗口一样的红色小标（原来的引号标记去掉），片段名宋体 22，下面一行游戏名、录制时间和“复制资料库路径”，活动不在标题区列出，挂在各体验事件上。录像下的播放条在纸面上，播放键是墨色圆钮，进度条的已播部分和滑块是红色。当前原话、最近操作、右栏（操作时间轴、原话、体验事件）都是纸面、不加描边；右栏页签是下划线页签，“最近按键 / 设备图 / 收起”是分段控件。红色只给播放头：时间轴上的播放线和时间、进度条、逐字稿里当前句的时间戳和竖线。操作时间轴里的各种标记（按键条、长按、口述条、缺口、窗口状态）和最近操作的键帽，配色和对比沿用安装版。

**选中态**（2026-10-22 用户定，全软件适用）：可以同时选多个的筛选（问题类型、界面来源等），选中是墨色底；同时只激活一个的页签和分段（证据 | 反馈、全部 / 已整理 / 待整理……），选中是白色底。

**间距原则**（2026-10-21 用户定，全软件适用）：组间间距 > 组内边距 > 组内间距；组内间距再按内容的亲密程度细分，越相关越近。例：洞察里议题与议题之间 16，议题行和展开内容的内边距 8 / 12，展开内容里标签、说明、子议题之间 8，同级子议题之间 4；场次详情里标题区、比例条、问题类型、关联洞察、体验事件这几组之间 24，问题类型块之间 16、块内边距 12 / 16、块内原话之间 8。

**基线对齐**（2026-10-21 用户定，全软件适用）：同一行里的数字和文字，不论字号，都按基线对齐，不按盒子居中。需要固定高度的条（标题栏、游戏页签、问题类型标题行、场次表格行）用“20px 行高加上下内边距”撑出高度，或在网格上居中整行，而不是把不同字号的字各自居中。验证脚本 `work/redesign/baseline/probe.cjs` 逐行量出每段字的基线位置，同一行相差不超过 0.5px 才算对齐。

**间距与圆角**（2026-10-21 用户指出间距混乱后收紧）：间距只用 4 / 8 / 12 / 16 / 24 / 32（`--s1`…`--s6`），不写其他数值；窗口四周 16，录制块与右栏之间 24，右栏各段之间 16，录制块内四边 24，卡片和提示框内边距 12 或 16，按钮左右 16、小按钮左右 12。圆角只用四档：小控件 6、按钮和输入框 8、卡片和面板 12、录制块和对话框 16。图示里的细缝（如问题比例条色段之间的 2px）不受此限。

**红色**：只用于录制（录制块）和回看的播放头。问题类型不再用红色系：困惑靛蓝、阻碍赭石、操作成本暗黄、负面评价紫，其他类型浅灰。

## 第五轮：内容克制（2026-10-25）

用户定的内容规则：不加只复述布局的副标签和说明；每个元素都要有明确用途，不放口号、装饰、卡中卡和重复信息；说明只留给异常状态和必须做的操作，次要细节放到展开之后；和现有界面保持一致，能删就删，改一处不重排整页。按此：

- 同一组数字只出现在一处：回看标题下不写问题分布；资料台详情不再有比例条和“N 个问题”汇总；数量为 0 的类型筛选不显示。
- 设置里只留会影响决定的说明：改游戏名不移动文件夹、删除游戏的后果、云端转写上传录音和可能收费、各种异常状态。字段名、布局已能说明的（麦克风只转写口述、游戏词库只用于这款游戏、资料总库的结构、启动时检查更新、模型下载位置和续传）不写。
- 设置的分节标题（录制、识别组件、转写、资料库、更新）用黑体 14 粗、墨色，是本节最醒目的字。
- 转写方式是单选分段：选中白色底，和其他单选一致。
- 洞察的证据树里，类型只在列头的类型筛选条上计数和筛选；各层议题下不再列类型标签（每张证据卡上已写类型）。顶层议题没有下级时，收起证据的那一行不再重复“N 条”（行尾的“支持 N”已给出）。
