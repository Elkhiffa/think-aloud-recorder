新会话按本文继续。开发计划第 1 节的全局规则仍然适用。接口细节见 `docs/agent-integration.md`，两份 skill 见 `skills/think-aloud-judgments/`（单场次整理）和 `skills/think-aloud-insight/`（跨场次分析与报告）。

## 1. 已确定的决定（由用户拍板，不要重新讨论）

- **手段服务分析。** OCR、小模型、外部识图、读客户端都只是丰富记录的方式，一律以“是否让体验设计分析更完善”来评估，用真实场次材料判断。
- **界面识别只覆盖全屏界面和侧窗。** 全屏界面到“顶部一级页签 / 左侧纵向图文页签 / 横向文本页签”的选中项；侧窗只需标题；背包是带左侧抽屉的特殊侧窗。HUD 和场景不自动识别，记录者会口述。
- **界面命名（2026-10-14 修订）。** 出现和上一屏不同的一级或二级页签即为新的一组界面，编号写 `组名/一级页签/二级页签`，组名取上一屏打开它时的入口文字，新界面有自己的标题且与入口不同时写 `入口名（标题）`（如 `活动（燕语江湖）/活动`，入口与标题不一致本身是导航定位的分析线索），入口只是“前往”“查看”类动作按钮时用标题；入口与界面都没有文字（无字图标、缩略图、快捷键）或入口文字随状态变化时，暂定组名、统一目录时列为冲突交用户确认（已定：属性界面用常规入口 `角色/…`，万相集用 `万相集/…`）；这一组里打开的侧窗归在组下。跳到新的一组用 `->` 记进 `route`，同组内切页签、开侧窗不记。同一组可从多个入口进入时只用一个正式编号（取出现最多的入口），其他写法为别名。提议的新界面不再逐个由用户确认：跨场次整理按规则统一收入目录（只改目录，不改场次结果），只把规则定不下来的冲突交给用户。
- **整理分情景。** 单场次整理不打议题标签，记录者明说“以前也遇到过”时写进陈述。唯一例外是 BUG：记录者明说 bug、把问题归到程序或引擎本身（如“可能是 Cocos 出啥问题”），或用跑测报缺陷的说法（重叠、裁切、适配、歪了、偏了），直接标 `BUG`。没明说的疑似缺陷由跨场次分析建为 BUG 的候选子议题，用户确认或驳回。用户之后记录时会更主动地说“bug”。
- **实例粒度要细，记什么不变。** 一条实例对应一句话里的一个点；记判断和带设计信息的观察，不记流程叙述、照念文案、对 NPC 的回应。
- **议题层级（2026-10-14 修订）。** 三层：洞察 → 议题 → 子议题。原来的顶层议题都升级为洞察；子议题多、能分组的洞察才加中间的议题层。洞察标题是几个字点名一类问题（如“目标明确时，仍有执行摩擦”），子议题标题是可检验的设计判断。洞察的新建、改名、合并由用户定，agent 每轮只提建议；议题和子议题由 agent 以候选新建。编号只是整理工作中的代号，界面上降为小字，挪动层级时编号不变。`TA-` 由用户定义；`N-` 是 agent 提议的候选；证据分支持和反例；`BUG` 是固定洞察，保持两层。报告里的“一、二、三”大标题只是这份报告的章节，可以跨议题，不是资料库数据。
- **安装版与新格式（用户 2026-10-13 选 A）。** 已安装的 0.7.x 只认旧格式结果，迁移后的三场在安装版里显示“需重新预处理”；在交付新版本前不在安装版里对这三场点重新预处理，新格式和洞察窗口先在开发版里用，交付时再打包安装。
- **工具不撰写报告。** 跨场次分析 agent 把报告写进资料库的 `洞察/*.md`，工具只展示并核对引用（AGENTS.md 已改）。报告的主题标题用几个字直接点名问题，引用缩小弱化，不打断阅读。
- **界面库与筛选（2026-10-14）。** 洞察窗口左栏在“报告 / 界面库”间切换。界面库是 Eagle 式多维度标签（`tags.json`），不是界面路径：维度（系统、活动 / 玩法）是可收起的大标题，标签是“封面在上、名称和条数在下”的网格卡片，文字不压图；封面默认取案例截图，可在证据卡右键“设为封面”。证据的标签 = 活动标签（主要来源，覆盖没有界面名的战斗和结算）∪ 关键词命中 ∪ 逐条增减。右栏每层显示判断类型分布，点类型或标签都成为全局筛选，可叠加、可清除。反馈入口统一为铅笔图标。
- **洞察窗口的交互。** 左栏报告、右栏证据各自滚动；证据按 洞察 → 议题 → 子议题 → 实例 排列，收起的证据树就是目录（不再单独显示目录），编号以小字挂在条数后；卡片以“类型 + 活动名”为标题，界面路径和归入理由弱化；每张卡只给一个时间段，点击在新窗口打开回看，停在时间段开头；时间段超过 2 分钟时停在说话前 10 秒；都不自动播放。议题、子议题和界面名默认接受，不再逐条确认；每个议题和证据卡上有“有问题”入口，反馈写进资料库根目录 `feedback.json`，由下一轮 agent 按 `feedback-list` 处理（2026-10-14 用户决定）。
- **本轮的议题归类（用户）。** C-2 成为 N-001；红点并入 TA-04（提示类引导注意力失效）；N-004 并入 TA-02（现为 TA-02.1）；0924 i12、i13 和 0929 i71 归 TA-01；0924 i21 归 TA-04.5（目标被替换）；TA-05 和 TA-01 同属“目标明确仍有摩擦”，TA-05 的摩擦来自机制和奖励效率，TA-01 来自界面；BUG.3–6 是 bug；“死亡后会补药”不是 bug，是体验问题 TA-05.4；TA-04 定性为“注意力引导未达设计预期”（红点、“新”和播报）；“再来一次的路径太长”按“阻碍在界面”从 TA-05 移到 TA-01（现为 TA-01.5）；TA-06A 与 TA-05.3 共用的 2 条证据两边都留；TA-02.1 里浏览类的发型、路牌留在原处。2026-10-13 用户确认了全部 49 个候选议题。

## 5. 仍存在的方法缺口

1. 回顾型判断的 `screen` 和所指按“话在哪说”还是“评价对象”取值没有规定。
2. 转写错字没有统一写法。
3. “以前也遇到过”的信号偏少，对照时刻不能指向别的场次。
4. “负面评价”定义过宽，约一半是显示问题、期待、阻碍或操作成本。
5. 说话人存疑、改口时才暴露的误判没有规定。
6. 没有画面证据的实例（提议界面中 60 条有 19 条），缩略图仍可能和界面名对不上。
