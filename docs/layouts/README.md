# 界面路径识别规则：每款游戏一份

情景轨道每隔几秒读一帧画面上的文字。**界面路径识别**在这之上判断：这一帧哪个页签亮着、页面主标题和侧窗标题是什么、手柄焦点框在哪里。这样 agent 整理时能知道玩家当时在“背包 › 道具”还是“外观 › 染色”，不用一帧帧截图去看。

“哪个页签算亮着”“标题在画面哪一块”每款游戏都不一样，所以规则按游戏分开写：本文件夹里一款游戏一个 JSON，文件名就是游戏名，例如 [`燕云十六声.json`](燕云十六声.json)。软件带了某款游戏的规则时：

- 首次设置可以勾选“创建燕云十六声项目并安装识别规则”；
- 资料库里还没有界面目录时，整理场次直接使用内置规则；
- 已有界面目录时，在 设置 → 游戏 →「界面路径识别」点「启用」，把规则写进目录（旧目录留在旁边）。

**目前只有燕云十六声有规则。** 其他游戏照常录制、转写、整理，只是情景轨道里没有页签和标题信息。

## 规则分两层

1. **识别方法**（`recognizer`）：怎么判断“亮着”、怎么找标题的代码，随软件发布，例如 `"yanyun"`（[`layout_yanyun.py`](../../layout_yanyun.py)）。资料库里的规则文件只能点名软件自带的识别方法，不能带代码进来。
2. **参数**：页签在画面哪一带、什么颜色算亮、标题的位置和字号、哪几个页签是一组。写在 JSON 里，同一个识别方法换一套参数，就能适配界面风格相近的游戏。

所以给新游戏加规则有两种情况：

- **界面风格和燕云接近**（亮着的页签是金色或高饱和的字，标题在左上角）：复制 `燕云十六声.json`，改成新游戏的名字，按下面的说明调参数。不用改代码。
- **风格差得远**（比如亮着的页签是底色块，或标题在正中）：需要新写一个识别模块 `layout_<游戏>.py`，在 [`layout_common.py`](../../layout_common.py) 的 `RECOGNIZERS` 里登记，随软件发布。请提 issue 并附上几张典型界面的截图。

## 坐标怎么量

所有位置都按**游戏画面高度**归一化，0 是顶，1 是底；横向距离也用画面高度做单位。这样 16:9 和带鱼屏能共用一套数值（燕云在 PC 上高度按比例缩放，左右按到边缘的固定边距排版）。量的时候截一张 1080p 的图：像素 y ÷ 1080 就是比例。区间写成 `[下限, 上限]`。

## 字段

以燕云的规则为例。

```json
{
  "recognizer": "yanyun",
  "tabs": { ... },
  "headings": { ... },
  "focus": { ... }
}
```

`tabs`、`headings`、`focus` 都可以省略；省略的部分不识别。只允许这四个键，多写的键会被拒绝。

### `tabs`：亮着的页签

| 字段 | 含义 | 燕云的值 |
|---|---|---|
| `gold.min_b` | 亮字颜色偏黄的最低程度：Lab 色彩空间 b 通道（蓝 → 黄）的值，越大越黄 | `12` |
| `gold.min_s` | 亮字的最低饱和度（0–1，最亮与最暗通道之差 ÷ 最亮通道） | `0.25` |
| `top_max_y` | 画面最上方这一带内的一排字算“顶部一级页签” | `0.1` |
| `text_bands` | 横向文本页签可能出现的高度带，可以写多条 | `[[0.12, 0.26]]` |
| `groups` | 你确认过的页签组：`screen` 是界面编号，`tabs` 是这一组页签的文字（至少两个）。纵列、横排都可以；在这类界面里依次看焦点金框、唯一的金色字、对比最强的底块来判断哪个亮着 | 见文件 |

`groups` 是最常加的部分：整理时发现某个界面的页签总是认不出来，就把这一组页签文字和界面编号加进来。

### `headings`：标题

| 字段 | 含义 | 燕云的值 |
|---|---|---|
| `main.margin` | 主标题左边到画面左边缘的距离区间（以画面高度为单位） | `[0.04, 0.16]` |
| `main.y` | 主标题中心所在的高度带 | `[0.045, 0.085]` |
| `main.height` | 主标题字高区间（排除小字和大号装饰字） | `[0.033, 0.055]` |
| `side.y` | 右侧面板顶部标题所在的高度带 | `[0.055, 0.085]` |
| `side.min_height` | 侧窗标题的最小字高 | `0.043` |
| `icon_tabs` | 纯图标页签（没有字）的界面名，这类界面用侧窗标题当页签名 | `["道具", "培养", "任务"]` |

### `focus`：手柄焦点框

| 字段 | 含义 | 燕云的值 |
|---|---|---|
| `hue` | 焦点框颜色的色相区间（度，0–360） | `[26, 44]`（金色） |
| `min_s` | 最低饱和度（0–1） | `0.31` |
| `levels` | 亮度档，从高到低依次尝试（0–1） | `[0.59, 0.35]` |

键鼠操作时没有焦点框，不报。

## 检查和试用

1. 校验格式：`runtime\python.exe -B -X utf8 agent_cli.py catalog-validate "<资料库>" "<游戏名>"`，规则写进界面目录后才会检查到。
2. 在资料库**副本**上挑几场有菜单的录像试跑：`agent_cli.py context-build "<场次文件夹>" --output "<工作目录>"`，再用 `agent_cli.py context-read "<场次文件夹>" --output "<工作目录>" --compact` 看每段识别出的 `tabs` 和 `headings`，对照录像核对。
3. 没报（缺字段或少了某一排）表示“没判断出来”，不表示画面上没有。宁可少报，也别把不是页签的字报成页签：误报会让 agent 写错界面路径。

燕云的规则是这样调出来的：在 26 场录像上抽查，干净抽样 90 帧报出 86 项、对 81 项；战斗、对话、过场 30 帧没有误报。字段细节见 [情景轨道与界面目录](../agent-integration.md)。
