# Think Aloud 0.10.0

开包即用：解压安装版就能跑完整的分析流程，不再需要源码目录或开发用的 Python。首次设置新增“准备分析”一步：一次点击下载文字识别组件并安装两份分析 skill；默认勾选“创建燕云十六声项目并安装识别规则”。燕云的界面路径识别规则随软件包，自动生效。另外修好了从 0.8.x 软件内更新失败的问题。

## 首次设置：准备分析

- 步骤变为：记录方法 → **准备分析** → 设备与转写 → 游戏与窗口 → 保存位置。
- 「准备分析」一个按钮做两件事：开始下载识别组件（后台继续，可以接着往下设置），并把两份分析 skill 装进这台电脑已有的 Claude Code / Codex。不点也能直接下一步，以后在设置里补做。
- 勾选“创建燕云十六声项目并安装识别规则”（默认勾选）：游戏名填为燕云十六声，资料库建在软件文件夹旁边的 `think-aloud-database`；完成设置时在资料库里建好界面目录并写入燕云的识别规则。只需要再选一下游戏窗口。
- 向导写明识别规则需要每款游戏单独定制，并链接到 [识别规则怎么写](layouts/README.md)。

## 从 0.8.x 更新

- 0.9.0 的完整包和增量包都带了一份字体来源记录 `app/tools/fonts/provenance.json`。软件内更新由**已安装的旧版**更新器检查新包，0.8.x 的更新器不认 `tools/fonts/`，整包拒收，报“更新包包含重复、链接、加密或受保护条目”，增量包失败后退回完整包也失败。这份记录运行时没有用处，0.10.0 起不再打进包里，构建时仍按它核对字体。
- 打包时逐条用 0.8.1 原版的路径检查过一遍，以后新增文件也逃不过。
- 只有一个增量包：它同时带上相对 0.8.1 和 0.9.0 变了的文件，两边都只下载增量包。
- 新增发布检查 `scripts/check_old_updater.py`：解压旧版完整包，用它自带的更新器去装新包（增量和完整各一次），装完核对版本和文件清单。

## 识别组件（文字识别）

- 设置 → 通用 →「识别组件」：下载、暂停、继续、重试，带进度。约 65 MB，是 RapidOCR、OpenCV、shapely、pyclipper、Pillow、six 六个固定版本的 wheel，只从 Python 官方软件源 files.pythonhosted.org 下载，逐个核对 SHA-256 后解压到软件文件夹的 `models\ocr\`。更新软件时保留，不用重下。下载中不能安装更新，关闭软件时自动暂停。
- 情景轨道、界面路径识别和提交时的界面核对都用它；开发 runtime 自带识别，不受影响。
- `agent_cli.py ocr-status` 报告文字识别是否可用。缺组件时，agent 只提示用户去设置里下载，不自行安装。

## 分析 skill 随包

- `think-aloud-judgments` 和 `think-aloud-insight` 随软件包放在 `app\docs\skills\`。
- 设置 → 通用 → 记录方法（首次设置第一步也有）→「安装分析 skill」：装进这台电脑已有的 Claude Code / Codex 技能目录，没装的 agent 不碰。旧副本内容不同时先整份备份到 `app\state\skill-backups\`，再写入；内容相同就跳过；你自己加进 skill 文件夹的文件保留不动。软件更新后再点一次即可同步。
- skill 改为“在软件目录运行”，安装版和源码目录都适用。「复制整理指令」多一行“软件目录”，agent 拿到就知道去哪里运行命令。

## 界面路径识别

- 版式规则 `docs\layouts\` 随软件包。资料库还没有这款游戏的界面目录时，整理场次直接使用内置规则，不需要任何操作。
- 设置 → 游戏 →「界面路径识别」：已有界面目录但还没有规则时显示「启用」，点一下写进目录，旧目录留在旁边；没有目录时写“已内置，自动使用”。这一行还给出旧场次的重建命令和“规则怎么写”链接。
- 新增 [识别规则怎么写](layouts/README.md)：每个字段的含义、怎么量坐标、怎么试用；别的游戏界面风格接近燕云时改一份 JSON 即可，差得远时需要新写识别模块。
- 新命令 `agent_cli.py layout-apply` 和 `agent_cli.py context-rebuild`：前者启用规则，后者按规则重建资料库各场的情景轨道（两场并行，可中断后重跑，已重建的跳过，每场一个日志在 `state\logs\context-rebuild\`）。游戏名和这个资料库不同的场次单独列出，不算失败。源码里的 `scripts\apply_layout.py`、`scripts\rebuild_context_tracks.py` 改为这两条命令的包装。
