# 软件更新

更新入口独立于录制预设，位于主窗口顶部的版本信息。首版采用手动检查、手动下载、确认退出后安装的流程，不在后台自动下载或强制重启。

## 日常使用

1. 打开“版本与更新”，点击检查更新。默认检查正式版；只有主动选择预览版时才纳入预发布版本。
2. 有新版本时查看版本、更新说明和大小，再下载。下载与录制状态分开；连接 GitHub 失败不会影响现有录制功能。
3. 下载和校验完成后，在录制、保存、整理、导出等工作结束时点击“退出并更新”。界面会说明需要关闭的回看窗口数量。
4. 更新在原安装路径完成，保留备份和安装结果；随后重新打开记录器。不能确认退出、文件仍被占用或校验失败时，不把更新标记为成功。

没有已发布版本与网络检查失败是两种不同结果。开发分支的提交不会自动成为软件可下载的版本；线上更新只识别 GitHub Release 的明确附件。[GitHub Release API](https://docs.github.com/en/rest/releases/releases) 提供版本、预发布状态和附件信息。

## 保留哪些内容

`config.json`、`state/`、`tools/obs/config/`、`models/`、`staging/`、用户词库及未知的非软件文件必须保留。资料库和外置模型保持原路径，不移动、不重新创建。本机加密 API Key 不需要解密再写回。

内置 `vocabularies/uiux-terms.txt` 只有在当前字节仍与旧包清单一致时才自动替换；用户修改过的词库必须保留。预设保存的词库快照不会被更新程序悄悄改写。

更新只处理包清单管理的软件内容。备份、失败记录和用户文件不能作为“清理旧版”的附带删除目标。目录名可以继续保持原名，界面版本从更新后的包元数据读取。

## 中断和恢复

安装前无法确认窗口或录制引擎退出时，不替换软件文件。若安装助手的取消尚未确认，主窗口会保留并提供“重试取消”，防止退出后发生意外安装。

替换后环境检查失败时，安装助手恢复旧版软件。遇到断电、文件被占用或启动尚未确认，更新结果会保留备份位置和恢复文件路径；关闭记录器、回看窗口及该目录的 OBS 后，双击事务目录中的 `恢复更新前版本.cmd`。恢复过程不强制结束进程、不删除备份，也不覆盖恢复过程中发现的额外个人修改。

## 发布方准备

先运行测试、构建并验收完整解压后的应用，再准备与版本标签对应的 Windows x64 软件 ZIP、依赖源码 ZIP 和 SHA256SUMS 文件。不要用 GitHub 自动生成的 Source code ZIP 代替可运行软件包，也不要把模型或本机配置打入附件。

正式版本采用 `vX.Y.Z` 标签；预览版本采用递增的预发布版本号并标记为 prerelease。版本比较以版本号为准，不以文件名的字典序或上传日期替代。应在发布说明中写明具体行为变化和已知限制。

`scripts/build_portable.py` 保留完整对应源码的公开分发检查。未通过这一检查的 candidate 包仅用于本地验证；不能重命名为正式包或改变元数据来绕过检查。当前具体缺口见 [构建说明](build.md)。发布 Release 是独立的对外操作，本地构建或推送开发分支不会自动公开附件。

SHA256 和包文件清单用于检测传输损坏与内容不一致，不代表独立的发布者签名。更新来源保持在本项目的 GitHub 仓库，不静默切换镜像、代理或下载站。
