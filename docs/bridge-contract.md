# Desktop bridge contract (v1)

Recorder and viewer have separate, restricted bridges.

Every public method returns `{ok: true, data: ...}` or `{ok: false, error: "user-readable message"}`. JavaScript uses `window.pywebview.api`. Never return or log saved secrets. Long operations launch a tracked background task; the UI polls `get_state()` every 1 second. Mutations are rejected while recording or a conflicting task is running. Native directory/file dialogs are handled by the service via `set_window(window)`.

`get_state()` data:
- `presets`: list of {id,name,vault}; `active_preset_id`: current stable ID or null. Presets independently save complete user-facing settings. Secret/model resources remain app-scoped.
- `default_vault`: {path,exists,is_directory,requires_confirmation}. The candidate is always the software folder's parent / `think-aloud-database`. A new portable installation with no config uses this absolute path; existing configs/presets retain their saved locations. `requires_confirmation` is true only when there are no presets and this candidate already exists (including a same-name file, which cannot be reused). No database is created at initialization. Before first save, this candidate's sessions are not enumerated/recovered, and readiness never writes a location probe without saved setup.
- `readiness`: {ready,checking,errors:[{code,message,step}],checked_at}. Applies only to persisted active preset. step=1 capture,2 transcription,3 location. Idle checks are asynchronous; frontend must not infer readiness from saved IDs or paths. Never enables capture from stale or failed checks.
- `config`: game, vault (resolved absolute path), preset, source (游戏窗口/整个显示器), window, monitor, mic, language (zh/en/ja/empty), hotwords, transcription_provider (later/local/qwen), configured, games. No OBS password or port, no cloud keys.
- `sessions`: list of {id, game, created, state, duration, segments, warning, error, path, test, in_current_vault, background_job, background_result} sorted newest first. `background_job` is the active queue summary or null; `background_result` is the last terminal summary or null, using state `completed/failed`. Summaries contain {id,session_id,game,state,detail}. After switching presets/vaults, sessions admitted to this app's queue remain visible for the rest of the app run, including their completion/failure result. IDs resolve within the current vault or these already admitted session paths; no arbitrary session paths accepted by action APIs.
- `background_jobs`: list of {id,session_id,game,state,detail}, in queue order. State is `queued` or `running`. At most one processing worker runs; this list excludes completed/failed jobs (see each session's `background_result`). It does not make the main recording CTA busy.
- `activity`: {busy, kind, status, detail, active_id, elapsed_seconds}. Foreground recording/control activity only; background progress and errors never overwrite it. Recording is authoritative only after OBS confirms start. Idle kind='idle', recording='recording', start='starting', stop='saving', processing='processing' (foreground connection checks), review='review', export='export', devices='devices'.
- `devices`: {mic: [{itemName,itemValue,itemEnabled}], window: [...], monitor: [...]} from actual OBS, initially empty. Never fabricate devices or meters.
- `model`: ModelManager.status() described below.
- `capabilities`: {cloud_key: bool, obs: bool, local_model: bool}.

Methods:
- `refresh_devices()` refreshes actual devices in a tracked job.
- `save_settings(payload)` saves a whitelist of config keys. Device values are itemValue, not display labels. Reject unsafe vault paths, invalid enums; save per-game preset. Switching game can use existing `config.games` client-side then save.
- `save_preset(payload,preset_id=null)` creates a new named preset or updates the specified ID. Payload contains `name` plus editable settings. Return fresh saved state; do not start capture. Name should be the game/project name. Optional transient `confirmed_vault` must be the absolute path explicitly confirmed for reuse or selected in the native picker; it is never stored in config, presets or sessions. For the first preset only, saving to an existing default candidate without matching confirmation returns `{ok:false,error,code:'VAULT_REUSE_REQUIRED'}` before template/config writes. The save rechecks existence and atomically creates a missing candidate to cover races after a UI snapshot. The UI must show confirmation rather than automatically retry. Cancel clears the path-bound confirmation. Later preset creation/editing does not require this first-run confirmation. Same-name files and permission errors fail without changing to another location.
- `select_preset(id)` applies all selected settings, switches vault/session list, and invalidates readiness until refreshed. Reject while recording or doing conflicting work.
- `choose_directory(kind)` returns {path} or {path:null}; kind vault/model/download. Only selects, does not write selected directory or import a model.
- `import_hotwords(current_text=null)` returns {text,count} after native multi-file .txt/.scel picker; merges with the unsaved draft when supplied. Does not save until settings/preset is saved.
- `choose_hotword_files()` returns `{files:[{id,name,words}]}` from a native multi-file TXT/SCEL picker. Cancel returns an empty list. All selected files must parse before any are returned. Names are basenames, never absolute paths; IDs identify normalized word content. The wizard appends unique files to its unsaved draft.
- `open_dictionary_site()` opens only `https://pinyin.sogou.com/dict/` in the system browser. It does not send preset names, words or local filenames.
- Preset/config fields `hotword_files` and `hotword_manual` retain dictionary snapshots and optional manual terms. Save recomputes and validates the flattened `hotwords` transcription input. Legacy flat vocabulary becomes manual terms. Session exports contain flattened words only, never file metadata.
- `start_recording(payload)` frontend passes `{}` to start from the persisted active preset. Backend revalidates before starting. `later` never requires a cloud key or local model. Other modes require their respective capability. No test-only source reachable through this method.
- `stop_recording()` holds recording ownership through OBS stop, raw-file validation and capture-source cleanup. After the complete stop returns, release the recording. `later` stays 待整理; other modes enqueue background processing using that recording's original settings. The next recording and preset switching are then allowed while processing continues. Do not leave active ownership ambiguous on failure.
- `process_session(id)` returns `{queued:true,id,session_id}` after admission to the serial background queue. Preserve session language/hotwords and use the current saved transcription engine/options, captured at admission. Preserve old transcript via the existing version mechanism. Reject `later`, the actively recorded target, and duplicate queued/running requests for the same target. Saved other sessions may be queued while recording.
- `open_review(id)` opens the current player in a native independent window and returns `{ready:true}` only after media metadata confirms loading. A player error or timeout returns `{ok:false,error}`. It may open older sessions while another session is recording; it does not overwrite capture activity. Viewer commands stay bound to the original session even after changing presets.
- Viewer-only bridge: `ready(error=null)`, `open_folder()`, `copy_path(kind='folder')` (folder/video/transcript), `open_document(kind)` (notes/transcript). No arbitrary paths or recorder control methods are exposed.
- Viewer layout preferences: `get_layout()` returns saved `columns`/`rows` video fractions; `save_layout(axis,ratio)` accepts only those axes and finite fractions in `[0.05,0.95]`. Changes merge under a process-wide lock into the bound app's `state/review-layout.json`, never into session files. Existing windows retain their own ratios; future windows load the preference. Browser exports use localStorage with a failure-tolerant fallback.
- `package_session(id)` exports session; `open_folder(id=null)` opens current vault or selected session. `open_raw(id)` opens existing raw video.
- `save_cloud_key(key)` calls existing DPAPI store (never return key); `verify_cloud_key()` uses current stored key and existing Qwen validator.
- `recover_cloud_task(id, task_id)` restores the existing Qwen task under its session lock, then returns `{queued:true,id,session_id}`. Queue processing keeps the original recorded settings/cache fingerprint; no repeated submission for uncertain results. Duplicate requests are rejected before replacing any saved task ID.
- `model_action(action, path=null)` actions download/pause/import; forwards to ModelManager. No model deletion API.
- `close_allowed()` internal app close handler: active recording, foreground job, queued or running background job prevents shutdown. Idle device/readiness polling does not block close. Native shell asks for safe completion during durable work; it never minimizes on close. Main close stops recorder checks; existing viewer windows survive and the native event loop exits after the last window closes. Model transfer pauses safely before idle close. `closing` in the main snapshot disables new work while waiting for already admitted jobs.

Queue admission persists `state='待整理'` and a `background_processing` marker containing the captured non-secret session settings. A restart does not automatically resume/re-upload queued or interrupted jobs: once no external session lock is held, leave the session 待整理 with an explicit manual-recovery warning. Preserve existing uncertain-cloud-submission guards. Recovery skips this service's queued/running sessions and re-reads metadata after acquiring the session lock, so a just-completed worker cannot be overwritten as failed. Queued settings are immutable snapshots; model files and DPAPI credentials remain shared application resources checked when execution begins.

ModelManager(root) API (separate owned module):
- `status()` -> {state: missing/downloading/paused/verifying/ready/error, model:'large-v3', path, downloaded_bytes, total_bytes, error, source, revision}. This method is cheap and non-blocking.
- `start_download(directory=None)` -> starts async pinned download to a default root/models/large-v3 or selected directory. No overwrite of mismatching existing completed files. Preserve partial files.
- `pause_download()` -> cooperative cancellation retaining partial data.
- `use_existing(path)` -> asynchronously validate and register external model directory, no copy.
- `resolve_model()` -> ready model path or None; registry reload supports another worker process. Only validated files with unchanged stats accepted; hash validation establishes the registry.
- `wait(timeout=None)` for tests / safe shutdown. Thread-safe state.

Frontend: native-looking local UI based on the approved prototype, but all mocked timers, samples, model downloads, and success transitions are removed. No public preview or mock mode in the shipped app. Local HTML error fallback is real, not a fabricated success. Format actual bytes with units. When a meter is unavailable say '未开始电平检测', never animate fabricated activity. Focus, keyboard access, loading states, and errors must remain clear.
